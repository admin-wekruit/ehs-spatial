# 工位拍照规范：通用标准视角 + 按盒子的面判断（给拍照的人和做检查的人）

**一句话：** 每个工位都按同一组标准视角拍（V1–V10，从入口量起，不随工位改），再按检查给出的**最多 4 张**补拍。每个物体是一个竖着放的盒子，有前、后、左、右、顶、底 6 个面；长由左右两面定，宽（进深）由前后两面定，高由顶底两面定，离地高度由底面定，所有高度都从同一个地面量。一个尺寸是靠定它的两个面的**轮廓边**量出来的：一张照片里，一个面的一条轮廓边 ≥ 80 % 在画面里、没被挡、按到这条边的直线距离 ≥ 10 px/cm，这张照片就"算"这个面；两个面都有 2 张这样的照片、方向相差 ≥ 30°，这个尺寸就是"高"。

**为什么：** 正对着一个物体拍，看得到前面的轮廓边，后面的边却不在轮廓上（除非从上往下看得到顶面的后沿），所以进深一般要从侧面看（V5/V6）。底面拍不到，也不用拍：底面靠四周侧面的**下沿**定；离地 0.5 m 以下的下沿要蹲下拍，镜头放平，这条边在屏幕上不低于下面那条三分线（V3/V4）。站着从高处往下拍时，深度误差会有一部分变成高度误差。

**现场说法：** 左 / 右指面朝工位（站在入口外往里看）时的左右；"外"是背离工位，"里"是朝工位里面；入口中心是入口两侧（两根入口立柱）的中点。所有位置都从**固定**的东西量起（立柱、防撞柱、围栏中点）；料车会被挪动，不能当参照。**距离只有一种：手机到目标的直线距离**（卷尺从手机量，或步测）。

## 1 面怎么定义（和盒子文件、页面同一套）

| 名称 | 定义 |
|---|---|
| 盒子 | SHARED FORMAT `boxes`（盒子拟合 `box_faces.py` 的结果，检查不自己建盒子）：中心 `centerNative`、三个轴 `axes` = [l 左→右, w 前→后, u 向上 = 报告地面法线]、尺寸 `sizeM` = [L, W, H] |
| 前面 / 后面 | 法线 −w / +w。前面是朝着现有照片的那一面 |
| 左面 / 右面 | 法线 −l / +l（面对前面时的左右） |
| 顶面 / 底面 | 法线 +u / −u |
| 长 L / 宽 W / 高 H / 离地 | L 由左右两面定，W 由前后两面定，H 由顶底两面定，离地由底面（它的下沿）定；尺寸的置信度见第 2 节（盒子文件 `dims`） |
| 看到这个面 | 面本身朝着相机、拍得到的照片（盒子文件 `faces.photos` / `status`）。只是参考，不算置信度：置信度看轮廓边 |
| 统一地面 | 所有高度都到同一个地面平面（报告的 n·X + d）：`bottomM`、`topM` |

## 2 一张照片算不算一个面、一个尺寸算不算量清楚（和盒子拟合同一套代码）

| 判据 | 数值 | 原因（一行） |
|---|---|---|
| 轮廓边 | 盒子投到照片上的外轮廓（凸包）上属于这个面的边：这个面和一个转向相机的面相交的那条边（面本身朝着相机时，就是它自己在轮廓上的边）；连着、转角 < 25° 的算一条边 | 盒子拟合就是用轮廓定面的位置 |
| 在画面里、没被挡 | 这条边 **≥ 80 %** 的点：点和它外侧 3 px 的点都在画面里、前面没有别的东西挡（铁丝网和报告没建模但已知的东西都算挡；离它 5 cm + 3 % 距离以内的不算"在前面"；离地 3 cm 以内的是地面标线，不算挡），并且看得到的部分 ≥ 20 px | 外侧被挡就分不清轮廓是谁的；太短的一段定不了位置 |
| 够近 | fx × 1 cm ÷ 手机到这条边的直线距离 **≥ 10 px/cm** | 设计取值（SHARED FORMAT）；这两部手机约 2.8 / 3.0 m 以内 |
| 两张、方向不同 | 两张从面中心看过去的水平方向相差 **≥ 30°** | 方向太接近，两张等于一张 |

一个面：**高** = ≥ 2 张照片算它、方向相差 ≥ 30°；**中** = 1 张（或 2 张但方向差不够）；**低** = 轮廓边看得到但不到 10 px/cm；**未验证** = 没有。一个尺寸（长 L = 左右两面，宽 W = 前后两面，高 H = 顶底两面）：**高** = 两个面都"高"；**中** = 两个面都至少"中"；**低** = 只有一个面算、或只有不到 10 px/cm 的；**未验证** = 两个面都没有。离地高度 = 底面（它的下沿）一个面。进深 W：正面的照片只有在后沿也在轮廓上时（侧面看过去，或从上面看得到顶面的后沿）才算后面，所以一般要侧面视角。补拍和标准视角只有在 200 次现场误差模拟（站位 ±0.2 m、手机高度 ±0.1 m、左右上下方向各 ±5°）里 ≥ 95 % 仍然算这个面，才算数。页面上把长、高、离地有"低"或"未验证"的物体标出来（只有 W 低不标），其余的可以平滑。

照片定不住的面（拟合时没有 ≥ 20 px 的轮廓，或和别的面互相抵消、σ ≥ 5 cm）用模型的尺寸，它定的尺寸最多"低"、没有 σ。掩码和盒子对不上（平均差 > 12 px，或在一张有掩码的照片里盒子盖住的掩码 < 80 %）时，盒子用显示模型的盒子（不发布压扁或只拟合了一部分的盒子），所有尺寸最多"低"、没有 σ，标出原因"掩码与盒子不符（N px）：尺寸取模型"；补拍也提不上去，要先修掩码或形状。

**特别目标**（部件的下沿、尺度参照物；它们不进 `boxes`，结果写在现场对照里）另有一套逐张判据：这个部件的一个面至少 80 % 在画面里、没被挡，视线和面的夹角 ≥ 15°，≥ 10 px/cm（fx × 1 cm ÷ 直线距离），2 张方向差 ≥ 30°；离地 0.5 m 以下的下沿还要 1 张低拍（手机 0.4–0.8 m、俯角 ≤ 15°）；尺度参照物（急停）要 2 张整个入画、≥ 11.1 px/cm、视线和水平面夹角 ≤ 30°。下沿高度只用**测量值**（`lower_edge` 的结果）或模型几何，**不用现场值**（现场值只用来验证）。

## 3 现场规则

| # | 规则 | 现场怎么做 | 原因（一行） |
|---|---|---|---|
| 1 | 前面有挡（防撞柱、料车）时**横向挪开**，光蹲低没用 | 绕着走开，直到它不在挡的东西后面 | 挡不挡由视线方向决定 |
| 2 | **竖拍、1 倍（不变焦）**，用原来那部手机 | 同左 | 检查用的是报告里这部手机的内参；变焦会改变 fx |
| 3 | 站着拍时手机举到脸前（离地约 1.5 m） | 胸口高度只有 1.3–1.4 m，偏低 | 规划按 1.5 m 算俯仰角 |
| 4 | 蹲拍时手机离地 0.4–0.6 m，**镜头放平**（打开网格线） | 指令里写的下沿不低于屏幕下面那条三分线 | 镜头放平时，三分线以上的点俯角约 ≤ 12–13°（这两部手机） |
| 5 | 不进防护区（光幕以内） | 同左 | 安全第一。检查只规划外面的站位；外面拍不到的面写原因 |
| 6 | 铁丝网（`seeThrough`）后面的东西按**被挡住**算，不规划隔着网拍 | 同左 | 网会挡住轮廓，隔着网拍的照片靠不住 |
| 7 | 报告没建模但已知的东西（`knownUnmodelled`，例如 030 的左侧安全围栏）按**挡视线、占地**算 | 不在它后面站，视线不穿过它 | 规划算不到它挡多少，按挡住算最稳 |
| 8 | 指令写"能不能站人未知，到现场确认"（超出建模范围，或现有照片没拍到这块地面）时 | 先过去看能不能站 | 报告里没有这块地面，可能有墙、料架或别的工位 |
| 9 | 站不了、又没有备选时 | 别换地方随便拍，拍一张挡路东西的照片，重新规划 | 随手换的位置大多不满足上面的判据 |

## 4 标准视角（每个工位都一样，从入口量起）

这一组对每个工位都一样（不在哪个工位上搜索、不按工位调）：位置都从入口量起（入口中心 = 入口两侧的中点，"往外" = 背离工位），V7 从尺度参照物量，V9/V10 从防护区的后角量。距离按"近处的物体直线距离 ≤ 2.5 m"定（这两部手机 10 px/cm 对应 2.8 / 3.0 m），45° 两张左右对称（两张方向差 ≥ 30°），V5/V6 在入口两侧 80°（不是 90°，免得视线擦着往里延伸的侧面围栏）。每个工位里，检查按新照片一样评估每一张：能不能站（能 / 未知：到现场确认 / 站不了）、靠它的面和目标、蒙特卡洛，只要它能拍清楚现在"低 / 未验证"的面或还差的目标，就要拍。

## 5 自动检查怎么给出要拍什么

```
python research-notes/workcell-capture-plan-2026-10-05/inputs/make_opts.py 090        # 盒子 + 测量的下沿高度 -> run-opts090.json
modal run modal_apps/workcell_view_checks.py --checks capture_plan --view VIEW.json --photos-dir DIR \
  --photo IMAGE_ID=FILE,... --layer-url URL --api ORIGIN --out 新目录 --opts run-opts090.json
```

只用 CPU，临时 `modal run`（8 CPU / 16 GiB，超时 1800 s，retries 0，min_containers 0），每个工位 1.9–4.1 分钟、约 $0.016–0.035。`opts` 的写法见 `inputs/opts090.json`：特别目标（`targets`：实体 id 前缀 + 部位 + `bottom` / `surface`；`edgeFrom` 指向 `lower_edge` 测量结果；盖住某个面的板 `coveredBy`，下沿 `bottomFrom` 也指向测量结果）、尺度参照物、固定地标、会挪动的东西（`movable`）、防护区（`keepOut`）、铁丝网（`seeThrough`）、报告没建模但已知的东西（`knownUnmodelled`）、入口两侧（`standardFrame`）；`make_opts.py` 再加上盒子文件（`boxes`，以及盒子拟合自己的逐张轮廓证据和限制 `gradeCaps`：检查用和盒子拟合同一套函数重算"现在"的置信度，`summary.beforeCheck` 列出不一致的，应为 0）。

输出（`results.json` 的 `capture_plan`）：`standardSet`（每个标准视角在这个工位能不能站：能 / 未知 / 不能，要不要拍，靠它的面和目标，完整指令）、`newPhotos`（最多 4 张补拍：位置、指令、蒙特卡洛通过率、备选）、`faces`（每个盒子的每个面：现在 → 补拍后、由哪几张、哪几张看到这个面、还差的原因）、`dims`（每个盒子的 L / W / H / 离地：现在 → 补拍后）、`targets`（特别目标）、`summary`；文件：`instructions.md`（给拍照的人，原样贴）、`coverage.md`（面 × 视角覆盖表，原样贴）、`topdown.png`（俯视站位图）、`V#-preview.jpg` / `newN-preview.jpg`（CPU 光线投射预览，两条灰线是三分线）、`render-check-photo1.jpg`。

补拍完成后，把新照片加进报告、重新做掩码和盒子拟合，再跑一次。那一次的盒子才是真正的结果。
