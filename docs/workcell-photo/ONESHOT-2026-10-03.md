## 0. 一个场景，一个对象一个模型（回应 3D 场景截图）

用户在 3D 场景里看到三件事：点不同物体，后面的模型会变；圈出的标识、信号灯、线缆托架、地面碎片很烂；场景不像“每个东西一个模型放在原位”。原因与改动：

- **模型会变**：机器人在四张照片里姿态不同，所以有四个按照片生成的机器人模型（`modelVariants`）。页面按当前照片替换机器人模型，点物体又会切换照片，所以背景里的机器人跟着变。
  - 改动：3D 场景固定显示每个对象唯一的当前模型；机器人用照片 4 的模型，并在卡片上写明。
  - 回归检查：`photo-scale-check` 断言切换照片不替换模型；把替换代码加回去，检查失败。
- **模型烂**：39 个 extras 对象（25 段地面胶带、7 个标识、5 个信号灯、1 个“工作平台”、1 个线缆托架）从来没有建过模型，用的是单张照片点云的原始碎片：边缘有飞点，同一物体每张照片一份（13 个对象有 2–3 份碎片），一条地面胶带被拆成 24 个对象，还有几个误检。
  - 新增 `scripts/workcell_extra_models.py`，在目录层面做三件事，规则见下表。
  - 每个剩下的对象只有一个代理模型：
    - 地面胶带：贴地的照片纹理四边形；
    - 标识：照片纹理平面四边形（点云太噪时，用最佳视角的图像矩形放到中位深度、面向该相机）；
    - 信号灯：清理后支持点的盒子；
    - 超出拟合工作区地面 0.25 native 以外的对象：只留照片观察，不放 3D 模型。线缆托架、工作区外的一段地面标线属于这种。
  - 支持点清理：objects 阶段的支持（不是外轮廓）腐蚀 1 像素，相机深度在中位数 3 MAD 以内。
  - 新运行由 `workcell_photo_objects.build()` 在末尾直接调用同一函数。
  - 结果：52 个对象 → 24 个，97 个观察 → 91 个，观察全部保留在合并后的对象里。

| 规则 | 本运行的结果 |
|---|---|
| 支持点落在地面平面上、又不是地面标线 → 并入地面 | `work-platform-1` → floor |
| 每张照片的支持都有一半以上落在机器人/小车/护板的同照片支持里 → 并入该对象 | `signal-light-6`、`sign-7` → robot（机器人红色部件和机身标签） |
| 地面标线的地面足迹相接（间隙 ≤ 0.06 native）→ 合并 | 24 段胶带 → `floor-marking-15` |
| 同类、清理后中心距离 ≤ 0.3 native → 合并 | `signal-light-3/4/5` → `signal-light-4`（同一盏灯；不同物体之间至少相距 0.9 native） |

- 目录变了，语义先显示 `not_bound`（Semantic object set differs from rendered scene），然后重跑。
- 冻结协议 `semantic-match-protocol.json` 的参考类别按 52 个旧编号写，所以另存 `semantic-match-protocol-2026-10-03.json`：类别、查询、阈值都不变，只把参考编号映射到合并后的对象。以后的 oneshot 要用这份协议。

## 3. 可见尺寸按本版本帧重测（P0 遗留）

报告构建时，按每个观察的 `source` 重建 objects 阶段用过的支持：

- SAM 实例掩码；护板实例另与 `guard-input.npz` 相交；
- 机器人各实例的并集；
- 选中的小车掩码；
- 围栏并集 ∩ 拟合平面带（平面以对象的 `geometryPlaneIndex` 为准）；
- 地面带；
- 按钮外包框。

然后在**本版本的帧和地面**上测量，测量函数与 objects 阶段共用 `measure_support`，**不用外轮廓多边形**。`visibleExtentFloor` 现在记录：`status: remeasured`、`floor: this revision's floor`、与本版本地面夹角 0，同时保留 objects 阶段的夹角与支持像素变化数。缺少重建所需输入（公开重放、实验上传）时不崩溃，标 `objects_stage` 并列出缺的文件。

另修了一处环境依赖。SAM 的原图分辨率 RLE 到 518×392 网格原来用 OpenCV 最近邻 warp，不同 OpenCV 版本会在边界差几个像素，因为 7.7 倍映射每 7 列就有半像素平局。可见尺寸取支持点的最大最小值，一个落到背景深度的边界像素就能改得很多：本轮 post-box-1 照片 2 的单视图深度从 8.85 变成 0.72 native。现在 objects 阶段和重测都改用逐元素 float64 的 `floor(x+0.5)` 最近邻 `decode_mask`。它在任何环境下结果相同，平局时由浮点舍入决定取哪一侧。

对本运行的影响：

- 云端目录是 objects 阶段在最终地面上测的（夹角 0）。和它相比，34 个观察的支持像素数不同，全部来自解码差异。
- 页面显示的可见高度只有 post-box-1 变了 −0.18 cm。

回归检查有两类：

- `check_workcell_revision_sync.py`，合成数据：
  - 原地面复现目录值；
  - 透空孔不进支持；
  - 平面过滤分开两截围栏；
  - 2° 倾斜地面按新地面重测，不显示旧值；
  - 各向异性带剪切仿射的解码与 float64 参考逐像素一致；
  - 100 格边界精确；
  - 复核幂等，只删碎片；
  - 截面清空后撤销离地值。
- `check_workcell_photo_report.py`，真实数据，不依赖报告自己的代码：
  - 用 objects 阶段 `build()` 在本版本帧上重建目录，报告的每个观察都必须与之逐字段相等；
  - 缺输入时必须标 `objects_stage`。
  - 变异测试：机器人只取一个实例、围栏带变窄、地面带变宽、解码平移一列，这四种改法都会让检查失败。

## 5. 光幕面身份逐图核对（P1-1）

证据：`evidence-2026-10-03/curtain-face-identity/`，含逐图原图裁剪、标签、度量和中文说明。另在本轮新拟合上复核：8 组中 7 组侧边线编号相同，右光幕照片 2 换了一条线段编号，目视仍是同一条立柱侧边。

- 外壳不是一块平板。每根光幕是两块黄色板：朝外的宽板 B，和开口侧斜置的窄边板 L；镜头条凹在两板之间。
- **四张照片用的不是同一块面**：
  - 右光幕：照片 2、3 只框住 B，照片 1、4 框住 B+L 的外轮廓；
  - 左光幕：只有照片 1 是 B 单独，照片 2–4 是 B+L。
  - 上下端边也在两块板之间切换。
- 拟合下沿是两块板下沿的混合：两块板下沿在图上差 30–45 px，约 0.05 native。所以 G 候选的光幕读数不是同一部位的测量。
- **单一矩形面模型不成立**，用固定一个矩形去拟合会把不同物理边合成一条边。
- 照片 1 最差，部分由面混用解释。审计还发现另一个可能成分：同一条立柱侧边在照片 1 比照片 3 偏右 27/40 px，符合相机 1 约 0.5–0.8° 偏航。之前的“相机偏差不能解释”诊断被面混用干扰过。这是**假设**，本轮按要求没有调相机。
- 下一步：
  1. 给每条线、每个端边标定它属于哪块板的哪条物理边，并跨图固定；
  2. 改为两板模型（B + 斜置 L），或只用 B 自己的边拟合 B；
  3. 之后再用无歧义的边（如立柱侧边）核对相机 1；
  4. 离地测量写明用的是哪块板的下沿。

## 6. 左右围栏下沿（P1-2）

证据：`evidence-2026-10-03/rail-identity/`，含原图叠加、围栏平面展开图、标签、度量和中文说明。

- **同一类构件**：两侧面板都是同型白色底部框管。竖杆焊入顶面，立面有螺栓头，下方是暗缝和立柱脚；两根光幕旁都实际存在这根框管。
- **测的部位不同**：
  - 右侧测点就在框管下沿。照片 1/3/4 与成员差 −0.011…+0.017 native。
  - 左侧是“观察到的下包络假设”，即平面 1 所有检测成员端点高度的 1% 分位，实为两个竖线端点之间的插值。在唯一清晰的左视图照片 2 中，它落在框管外立面上，比框管下沿高 48 px。
  - 所以上一版的左 − 右 = 5.79 cm 不是同类比较。
- 诊断值，不写入报告：
  - 在同一拟合平面上读左侧下沿，得 0.262 native ≈ 17.93 cm，左 − 右 ≈ −0.63 cm。
  - 平面深度的不确定性把它放在 15.7–20.2 cm 之间，点图立面深度给出上界 22.55 cm。
  - 只有一张清晰左视图，左右是否同高无法定论。本轮不强制同高。
- **已改**：
  - 端点表（schema 3）给每个围栏测点标 `railPart`：`lower_edge` 或 `lower_envelope_hypothesis`。
  - 假设点在页面上标为“围栏下包络假设”，说明它不是下横梁下沿。
  - 含假设点的比较（左光幕 − 左围栏、左右围栏差）不再计算，改为在 `excludedComparisons` 写明原因。页面显示“不比较”，结构化提问也回答原因而不是数字。
  - 回归检查：同步检查、端点检查、提问检查。
- 要真正测出左下沿，要改几何阶段，本轮没改：
  1. 把平面下三分之一中最低的长“下暗上亮”水平边作为下横梁证据，或按 native 面高上限配对。现在按线段长度比例配对，配不成。
  2. 从另一个不被护柱遮挡的视角三角化左下沿。
