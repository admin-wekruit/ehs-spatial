# RGB 深度、距离误差与可借鉴的自动驾驶路线

2026-10-01。对象：现有四张 BOR1 照片，按钮整体高 10 cm、主体最大直径 8.5 cm、红帽直径 4 cm。目标仍为一次运行输出可交互模型，并检验三处离地误差是否各小于 3 cm。

本文记录调研当时的状态：公开一手资料调研和保存产物审计，没有重新运行深度网络，没有新 GPU 调用。文中模型能力来自作者公开资料；对本项目的适用性是工程判断。随后执行的 GPU 对照、修正与失败记录见 [RGB 深度实验](RGB-DEPTH-EXPERIMENT-2026-10-01.md)；不要把本研究记录当作最新运行结果。

## 1. 结论

1. RGB 可以恢复深度和米制几何，但精度取决于相机、跨视图对应、尺度依据、局部边缘与测量对象定义共同成立。
2. 本照片链路使用 **MapAnything**；视频链路使用 DA3，不能混为一次算法实验。现有照片程序已经联合输入四张图，不是逐张完全独立猜深度。
3. 已确认小标尺在神经网络输入中很小、两个直径未进入已发布的相机联合优化、目标投影无法通过留出视图检查，以及离地端点/真实地面支持不足。无法仅凭这些结果把误差百分比分配给深度网络、焦距、分割或地面。
4. 最短路径是修复原图目标观测、完成三尺寸联合几何约束，再在同一测量链下比较深度算法。每次只改变明确的一项，才能确定换模型的贡献。
5. 借鉴特斯拉的多视角、时间一致性、标定和离线重建验证思路。公开材料没有给出其当前完整生产实现，也没有提供本场景 sub-3 cm 保证。

## 2. 为什么“像素有深度”还不等于“离地距离准确”

在理想针孔模型中，某像素的相机轴向深度为 z，有：

```text
相机内的点 = z × inverse(K) × [u, v, 1]
场景中的点 X = R × 相机内的点 + t
单位地面法向 n、地面偏置 d：离地 h = scale × (n·X + d)
```

因此同一个 h 会同时受像素/对象对应、z、K、R/t、scale、n/d 影响。网络可以直接联合输出其中数项，仍需用源观测检查它们的真实性。把模型输出的点再投回它自己输出的相机，是内部自洽检查，不能单独验证真实距离。

已知一个长度可以消除正确重建中的一个统一尺度自由度；它不能自动修复局部拉伸、错物体、错相机姿态或错地面。按钮三个尺寸比单一高度提供更多约束，但并未提供每个部件的完整 CAD、每张图的焦距或相机到按钮的距离。

两个直径应通过圆形/曲面的投影约束使用。不同照片中轮廓的左右切点通常不是同一对物理点，不能直接作为固定三维点匹配。黄色主体的收窄形状、红帽的圆顶以及灰色底座的未知尺寸也须保留为待估形状，不能以理想圆柱假设强制“校准正确”。

误差量级示例（不是本次测得的误差）：地面法向若偏 1°，距离支撑中心水平 1.5 m 处可产生约 `1.5 × tan(1°) = 2.62 cm` 的高度偏差。一个 20 cm 间隙若全局尺度偏 10%，也会偏 2 cm。两项还可能与深度、边缘误差相关，不能简单当作独立噪声平均消除。

## 3. 本次直接从代码和产物查到的证据

审计脚本：`research-notes/workcell-depth-research-2026-10-01/audit_depth_inputs.py`；输出 `audit.json` 和 `depth-bottlenecks.png`。审计在本地只读取保存数组和结果，未改变模型/测量文件。

### 3.1 输入分辨率限制了小物体深度细节

四张原图均为 3024×4032；保存的 MapAnything 推断栅格均为 **392×518**。

- 照片 2/3/4 的红色颜色区域在原图宽 53/46/47 px，映射到推断栅格仅 **6.87/5.96/6.09 px**。
- 整体按钮包围框在推断栅格高 **17.61/14.24/14.76 px**。
- 以上为现有颜色轮廓/包围框的跨度，未把它们当作独立验证过的物理边界。

这意味着深度初值对红帽、黄色壳体、灰色底座的分辨能力有限。把输出图片放大不会恢复被缩小丢掉的观测；原图局部精细匹配和边缘提取仍可提供额外信息，不能据此断言四张原图本身不够。

代码位置：`scripts/workcell_map_worker.py` 调用 `load_images_with_metadata`，`modal_apps/mapanything_app.py` 记录真实缩放/裁剪变换并校验 RGB 栅格；原图与推断图之间不是任意按宽高猜比例。

### 3.2 标尺并未完整进入已发布的相机求解

发布版统一倍率仍是 `0.10 / nativeHeight = 0.5966604006 m/native`。两个直径已用于显示模型和独立候选实验，但没有成功联合校准相机/结构。当前未提交的联合求解草稿不构成实跑结果。

原相机下，红帽圆候选的留出照片最大切线误差分别 **116.71、41.07、30.77 原图 px**；红色区域自身宽仅 46–53 px。黄色圆候选对应误差为 **145.07、56.06、39.10 px**。这证明该候选不能解释未参与拟合的照片；不能单独归因为深度网络，因为轮廓、圆形假设和相机也参与了该检查。

源：`workcell-sub3-metrology-2026-10-01-c/original-cameras/results.json` 的 `calibration.candidates`。

### 3.3 多张照片不等于目标处存在充分多视角约束

方形原图像素 COLMAP 对照保存了 692 条 SIFT 轨迹：681 条只有两张图，10 条有三张图，1 条有四张图。只有 **11/692（1.59%）** 跨三张以上图。轨迹仍是全图拟合候选，不是独立真值；四图共同可见的目标边缘还需单独验证。

原 MapAnything 的 raw-K 中 `fx/fy` 为 0.9982–1.0021，已经接近 1。因此当前证据不支持把问题简单归咎于横纵像素比例；焦距绝对值、主点、畸变和外参仍未经现场标定。此前方形像素相机对照也未使所有目标通过。

已有 SIFT/COLMAP、LK、LIMAP、LoFTR 实验必须复用。此前护板限定区域的 LIMAP 稳定三维线为 0；背景重投影误差下降也未证明护板或光幕实体端点准确。见 [准确性计划](ACCURACY-PLAN-2026-10-01.md) 和 [交接](HANDOFF.md)。

### 3.4 离地距离还有独立的端点和地面问题

原点图路线的平面有 11,399 个入选像素点；在高度标尺下，P95 平面残差约 **1.64 cm**。这些点可能相关，平面身份仍标记为未确认混凝土地面。导轨/安装板附近点可能污染拟合；残差小不能排除整体偏高或偏低。

另一条相机路线从 RGB 匹配恢复了 24 个平面点，但三个目标附近的支持不足。两侧光幕没有通过同一实体下沿的跨图验证。围栏 C 估计仍为 16.22 cm，对现场 20 cm 偏低 3.78 cm；该差值不能归为某一个已知原因。

另外，worker 在 `mask_edges=True` 外又剔除相对深度梯度大于 0.08 的像素。此操作用于抑制边界飞点，但旧对象测量取有效分割点的极值，未必落在物理底边。现有光幕测量研究已经改查原图实体边线，需完成跨图对应才可替换。

### 3.5 标尺分割问题与深度问题同时存在

已核查：`emergency stop button` 的四图 SAM 输出均为空；`red emergency stop switch` 在照片 2/4 的候选落在画面中央，和右侧按钮不重合。主报告按钮轮廓来自矩形包围框；测量用 HSV 最大连通域的凸包。阴影/反光导致颜色与物理边界分离、凸包跨过凹口，是需要单独检查的机制。

这部分应先在原 JPEG 上修正并核验；三个实物尺寸不能用于把错误颜色轮廓硬拉到正确大小。

## 4. 特斯拉路线能借鉴什么

Tesla 的公开 AI 页面描述了按相机提取图像信息、聚合全部相机的视频生成鸟瞰空间表示，并跨空间和时间组合传感信息构建训练真值。官方维修说明也明确要求相机自标定，在相机位置改变后重新标定。这些是可核查的公开机制；不能把页面描述当作当前 FSD 每个网络的完整实现清单。[Tesla AI](https://www.tesla.com/AI)、[官方相机标定说明](https://service.tesla.com/docs/Public/diy/models/en_us/GUID-D6F7D1BC-193D-4A2E-99B0-E3BA3D41BDE2.html)

对本项目的工程启发：

- **共同坐标与标定**：不同视角先建立一致的相机/场景关系，尺寸和模型都消费同一几何结果。
- **充分利用移动视差**：视频可以提供连续跟踪和更多观察；四张照片则集中使用可靠对应。重复输入相近帧、只旋转不平移不会自动增加可靠深度约束。[COLMAP 拍摄与重建指南](https://colmap.github.io/tutorial.html)
- **跨观察验证**：在未参加某次拟合的照片里检查真实目标边缘，区分遮挡、身份混淆与几何误差。
- **大规模学习与本场景验证分开**：预训练提供初值和补全能力，我们仍需要本工作单元的独立距离验收。无需在本轮训练一套 FSD。

Occupancy/BEV 表达“哪里有物体、可用空间在哪里”；它有助于组织空间，但不会单独提供小按钮轮廓、薄板夹角和物理底端。把表示形式换成 occupancy 或高斯，也不会直接消除上述观测误差。

## 5. RGB 深度方向比较

以下是候选适用性判断，未在本四图上跑新成绩。

| 方向 | 借鉴/实验价值 | 本场景关键条件 |
|---|---|---|
| MapAnything / DA3 / VGGT 多视图前馈几何 | 快速联合估计相机、深度/点图；保持一次运行的速度目标 | 保留共同坐标和原图局部约束；输出仍须用按钮与留出图验证 |
| Depth Pro 高分辨率单图深度 | 针对细边缘、薄结构做局部深度对照 | 单图预测不能当作跨图真实一致性；需要共同几何融合 |
| MASt3R + SfM/BA/MVS | 增强对应关系，用跨图误差优化相机/三维结构 | 重复栅栏、反光和弱视差仍须过滤；不是“匹配点越多越准” |
| Metric3D v2 | 深度与表面法向一起预测，可对照地面方向 | 焦距设置会影响几何；法向输出不是现场地面真值 |
| Video Depth Anything | 视频深度时间一致性；有 metric 模型 | 当前四张静态照片不具备长视频时序；稳定不等于绝对精确 |
| MetricAnything | 新的 metric depth / pointmap 候选 | 按实际开放的 checkpoint 区分输入；不能把按钮尺寸当作稀疏深度 |
| Fast-FoundationStereo | 校正图对上的快速稠密视差，有利于可观测区域精化 | 需要去畸变/极线校正；米制点云还需要内参及米制基线 |

一手来源与实施注意点：

- [MapAnything 官方仓库](https://github.com/facebookresearch/map-anything) 支持图像与已知内参、深度、相机位姿的组合输入。我们现有 worker 只传图片；后续可把经过验证的几何条件接入，避免重复开发接口。
- [DA3 官方说明](https://github.com/ByteDance-Seed/Depth-Anything-3) 区分 any-view、metric 与 nested：any-view giant 本身不应直接解释为米；nested 用 metric 模型定尺度。单独 metric 输出换米涉及焦距。ray-head 位姿模式值得做一个固定配置的精度对照，不能把其公开基准增益当作本项目增益。
- [VGGT 作者项目](https://vgg-t.github.io/) 联合预测相机、点图、深度和轨迹。研究中的快速前馈结果不包括本报告全部分割、生成模型、导出和发布耗时。
- [Apple Depth Pro](https://github.com/apple-aiml-research/ml-depth-pro) 重点是高分辨率、边缘与焦距估计；作者报告 2.25 MP 深度约 0.3 s，是其设置下的单模型指标。实际开放实现与论文模型也不是完全相同成绩。
- [MASt3R 官方仓库](https://github.com/naver/mast3r) 提供匹配及 SfM 集成；[COLMAP 指南](https://colmap.github.io/tutorial.html) 说明先求相机/结构，再做 MVS 和网格。已有 LoFTR/COLMAP 结果应作为对照基础。
- [Metric3D 官方 FAQ](https://github.com/YvanYin/Metric3D#-q--a) 明确指出焦距错误会使点云变形。它说明“深度图看着顺眼”仍可能和三维形状冲突。
- [Video Depth Anything](https://github.com/DepthAnything/Video-Depth-Anything) 已提供 metric 与流式模式；其说明同时报告流式推断可能损失精度。不能只读实时速度而忽略配置差别。
- [MetricAnything](https://github.com/metric-anything/metric-anything)：当前仓库列出 student depthmap 输入 Image+Focal、student pointmap 输入 Image；带稀疏深度的 teacher 仍列 TBD/Coming Soon。按钮的已知高度/直径是物体内距离，尚不是像素到相机的已知 z。
- [Fast-FoundationStereo 项目](https://nvlabs.github.io/Fast-FoundationStereo/) 与[官方输入要求](https://github.com/NVlabs/Fast-FoundationStereo) 提供速度与校正条件。当前可先研究两张照片经可靠相机优化后的图对，不要求本轮购买新设备。

## 6. 最短实验顺序

冻结相同四张原 JPEG、三尺寸、目标定义和当前结果，沿用已有相机与匹配产物。现场 20/24/24 cm 只在输出固定后评估，不能参与求解或选结果。

1. **观测对照**：核验同一个按钮、三个部件轮廓、真实混凝土地面与光幕实体下沿。固定深度初值，对比原观测与修正观测，量化分割/端点的影响。
2. **联合几何对照**：固定模型初值，完成三尺寸、目标轮廓、相机参数与跨图对应的联合约束。形状未知量需显式保留；检查尺度/相机是否可辨识。留出某图时不得用该图标尺观测初始化该次拟合。
3. **深度模型对照**：沿用同一有效测量链，比较当前 MapAnything 与 DA3，并用 Depth Pro 检查关键区域边界。相机变更后重新求相应几何，不能用新相机加旧世界坐标模型直接宣称校准完成。
4. **完整 oneshot 验收**：再把胜出的配置接回模型生成/摆放/报告，一次输入、自动多步计算；内部优化迭代仍可封装在一次调用内。核对卡片数值、空间测量线、原图投影和导出 GLB 一致。

每个对照必须记录：三处各自误差与缺失项、留一照片变化、关键边缘原图像素误差、真实地面的支持范围、端到端与阶段耗时、峰值显存和增量支出。当前只有少量已公开开发检查值，不足以声称其他 workcell 也达到 3 cm。

重计算放在临时 `modal run` 的 2×A100。全局几何与原图局部分割/深度对照可分卡并行，随后联合优化与已有模型输出汇合；每轮实测速度，保留几分钟的完整流程目标。研究脚本不新增 GPU 开销。
