# Panoptes 产品完整定义（先定清楚，再做）

原则：**不再 shrink**。下面每一项都是必须有的；做出来的东西少一项就是没完成。
每项后面的「验收」是唯一算数的标准。

---

## 0. 产品是什么

工位安全合规 harness：操作员上传 1–4 张工位照片 → 系统重建三维、识别全部装置与物体、
按规则判定 → 交付一份**完整可交互的报告**（判定、证据、CAD、3D、检测清单、测量），
支持 review 签字、agent 对话补测/追问、历史回看。**一个产品，一套最新分析，一份完整报告。**

---

## 1. 产品面（Tabs）— 五个，缺一不可

| Tab | 职责 | 现状 | 差距 |
|---|---|---|---|
| **提交 Submit** | 上传 1–4 图、相机高度、policy 勾选、提交；跑完直接在本页给「第一眼结果」 | 有（叫 Workbench） | 第一眼结果太薄：CAD 不完整、3D 视角不对、VLM/检测层看不到 |
| **报告 Report** | 完整交互报告 + 3D + CAD；**同时就是历史**（时间倒序列表） | 有 | 报告内容缺段（见 §3）；升级机制刚做好 |
| **Review 审核** | 审核员对每个 run 签字：确认 / 推翻（改判定 + 理由 + 署名），记录进 run，报告顶部显示审核结论 | 后端函数在（save_disposition）UI 被我删掉了 | 需要作为独立 tab 回来，且和报告联动 |
| **Agent 对话** | 基于某个 run 聊：追问（grounded QA）、补测（"右边黄色柱子帮我量一下"）、纠错（"这块不是围栏"）、调整策略、口头描述缺漏 | 有两个入口（补测 tab 里的一句话补测 + Workbench 下面的问答） | 分散、没有统一会话；缺"纠错/重标"动词；结果不回写报告 |
| **Video** | 固定机位视频的越线/闯入 | 有 | 本轮不动 |

History 不做独立 tab：报告 tab 的时间倒序列表就是历史，但**每行要显示**：时间、判定状态、审核状态、缩略图。

## 2. 第一眼结果（提交页跑完立即显示）— 必须包含

1. **判定卡**：状态、间距数值±误差带、命中的 policy 明细、warnings、climb review
2. **3D 点云** —— **视角必须锚定在相机**：
   - 初始相机位姿 = 第 1 张照片的相机位姿（位置 + 朝向），看到的就是拍照时看到的
   - 轨道旋转中心（重心）= 相机正前方地面上的点（不是点云质心——质心会被远处背景拖走）
   - 上方向 = 地面法线；地面网格与相机原点标记可见
   - 4 视角时提供"切到第 N 个相机"按钮
3. **CAD 平面图** —— 用 inventory 的完整 CAD（`floor_plan.png`：全实体、墙线、cell 矩形、尺寸标注、对象表），**不是**现在那个只有一个围栏多边形的 topdown。深链没跑完前先显示快速版并标注"完整 CAD 生成中"，跑完自动替换
4. **VLM + 检测层可见**（现在完全看不到）：
   - VLM 枚举清单：VLM 说场景里有哪些东西（phrases）
   - 每个短语的去向：有实例 / unresolved（原因）—— 兑现"枚举必有交代"
   - taxonomy 检测清单：检出（编号+类别+SAM 分数）/ 缺失 / 拒绝（裁剪自检理由）
   - 检测叠加图（编号框）
5. **明确的时间预期**：快速结果多久、完整报告多久、当前深链阶段

**验收**：新图提交 → 55s 内看到 1、2、快速 CAD、5；深链完成后本页 CAD 自动换成完整版、4 全部出现。3D 打开第一帧就是拍照视角。

## 3. 完整报告（报告 tab 与下载的 HTML 同一份）— 段落清单

现有 7 段保留，**补 6 段**，顺序如下：

1. 头部：run 信息、判定徽章、**审核结论**（新）、分析版本戳（新）、时间
2. 判定明细（policy 逐条：状态/阈值/测得/证据 fact id/原文）
3. **VLM 枚举与去向**（新）：短语 → 实例数 / unresolved 原因
4. 装置检测清单（taxonomy A–F，检出/缺失/拒绝 + 叠加图 + 图例）——现有，补上**拒绝项及理由**
5. 原图点选（点照片高亮实体，含补测）——现有
6. **CAD 平面图 + 交互平面**（现有 SVG + 距离矩阵；补：**cell 矩形约束结果**——四边/开口边/被判为邻 cell 的结构、Manhattan 角度）
7. 交互 3D（相机锚定，同 §2.2）——现有 iframe，改视角逻辑
8. 实体测量表（物体/数量/高/尺寸/距相机/足迹方法）——现有，补**尺度来源与置信**（moge_anchor 0.91 这种）
9. 回投验证（红点压接地线 + 偏差 %）——现有
10. **证据图集**（新整合）：每帧 evidence overlay、深度渲染、点云透视/顶视
11. 人工补测记录（框选/agent 补测 + 是否回灌判定）——现有
12. **Agent 对话记录**（新）：这个 run 上的问答/纠错，附时间
13. **Review 记录**（新）：审核员、决定、理由、时间
14. 附录：warnings 全量、unresolved 全量、run 参数（相机高度、policy 集、后端来源）

**验收**：对 BOR1 run 生成的报告包含以上 14 段全部；下载的 HTML 与 tab 内 iframe 一致；文件自包含（离线可开）。

## 5. Agent（统一为一个会话面）

一个对话框，绑定当前 run，五个动词，全部回写 run 并反映到报告：

| 动词 | 例句 | 后端 | 回写 |
|---|---|---|---|
| 追问 | "围栏离机器人多远？" | grounded QA（SceneMap facts） | chat.jsonl → 报告 §12 |
| 补测 | "右边黄柱子帮我量" | agent_refine（VLM 定位 + SAM + 测量） | refinements + 可选回灌判定 |
| 纠错 | "这块不是围栏，是导向挡板" | 改实体 label → 重评 policy | inventory/scene 更新 + 报告 |
| 描述缺漏 | "机器人后面还有一台设备没识别" | 走补测 + 加入 unresolved 消化 | 同补测 |
| 调整策略 | "这个 cell 用 0.8m 间距规则" | 改本 run policy 参数 → 重评 | policies.json + 报告 |

**验收**：五个动词各一条真实指令在 BOR1 上跑通，报告 §12 出现记录，判定/实体相应变化。

---

## 6. Review

- 独立 tab：选 run → 看报告摘要 → 审核员/决定（确认/推翻）/推翻后的状态/理由 → 保存
- 保存后：run 里 `disposition.json`；报告头部显示审核徽章；历史列表显示审核状态
- **验收**：BOR1 推翻为 PASS 并写理由 → 报告头部与历史行同步显示

---

## 7. 做的顺序（每步交付可验证）

1. **3D 相机锚定**（提交页 + 报告内嵌 viewer 同一份代码）
2. **CAD 统一**：提交页用完整 CAD；深链完成自动替换
3. **VLM/检测层进提交页 + 报告 §3/§4 补全**
4. **报告补齐 14 段**（§1 头部、§6 cell 矩形、§8 尺度、§10 证据图集、§14 附录）
5. **Review tab 回归 + 报告联动**
6. **Agent 统一会话 + 五动词**（纠错/调整策略是新代码）
7. 历史行信息（状态/审核/缩略图）
8. 全量回归：414+ tests、三个 canonical run + BOR1 报告逐段核对、E2E 提交一次全流程

每一步：代码 + 测试 + 在 BOR1 上实测截图，才算完成。
