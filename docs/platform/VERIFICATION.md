## 三条端到端链路的实际覆盖

### 漏掉的小物体

真实历史工位按钮和没有 mesh 的对象可以在对象树、照片和工作台中选择；切到它们时不会销毁整个场景。人工补充观察和模型操作会产生新 revision。合成阶段测试覆盖 49 像素小 mask、无深度、重复 crop、两个相似按钮、父子物体、旋转相机和非单位尺度。

实际新照片的付费分割、SAM 3D 生成和定位质量没有跑完，因此这条链路的模型部分不能标为端到端完成。无定位支持时，资产可成功生成，但不能显示伪造的准确位置。导入的历史模型均保留未确认放置来源；用户接受放置属于人工修改，不提升观测精度。

### 修改布局并分享

浏览器实际创建项目、上传照片、创建参数对象、修改尺寸、保存、撤销、重做、刷新、创建规划分支、发布固定报告，并在访客报告中保存独立副本。原重建、规划分支和报告分别有固定身份。数据库测试覆盖并发基础版本冲突、旧任务结果不覆盖新 head、跨项目写入拒绝。

EHS 浏览器测试实际保留旧 FAIL 和未知适用性，新增带来源的人工事实后得到新的评估，补证据请求引用新评估和精确事实，再发布固定报告。这个测试证明版本和判断路径，不能证明真实机器的功能安全。

### 替换基础设施

暂停本地 API/worker 写入后导出 PostgreSQL，复制逻辑 key 不变的资产，恢复到新的本地数据库和文件目录。290 个资产、21 个 revision、9 份 publication 均通过哈希核验；新执行器启动实际子进程导出同一固定场景 JSON，随后 291 个资产仍通过核验。旧报告 ID、revision 和 API 资产解析不变，原数据库未被写回。

这次演练证明本地 PostgreSQL/目录/进程切换。未将其描述为 Supabase Storage S3 或 Modal 的实地切换验证；后两者仍需真实服务配置。

### 实际 Blender 任务

通过正式 API 对固定工位 revision 创建任务 `7c703c1b-0790-499d-b8e0-bd75d8e68a78`。后台本地 worker 生成并重新打开 Blender 文件，随后保存 GLB、Blender、manifest 和校验报告四个不可变资产。四个资产经实际 HTTP 下载后全部通过哈希与大小核验，分支 head 没有改变，模型调用为零。

这次单次 worker 耗时 8.84 秒，导出 48 个对象、约 52 万三角面。22 个未确认放置或缺少网格的对象在 manifest 中保留，任务如实为 `incomplete`。该时长只是已有资产的本地导出时间，不是图像分析/生成速度或性能分布。

## 已知产品边界

- 缺少实际测量或地面依据时，物理高度和倾角为空。模型单位、局部轴角度、模型高度与现场实测分别展示。
- 旧研究资产缺少原始深度/pointmap/confidence 时，导入记录标记必须用新 Capture 重算；不从预览图恢复伪证据。
- 无法从现有证据证明跨照片身份的历史观察保留待关联状态。不会按名称合并两个按钮或把围栏与其按钮盒合并。
- 照片命中目前使用原图边界框，重叠时优先小对象；不宣称是完整 mask 像素命中。
- 全局平台文案中英切换不清空状态；JDM 第三方编辑器自身的部分内部菜单仍为英文。未修改供应商 DOM 或另写一套编辑器。
- 基础纹理材质与混合材质槽经过 Blender 检查。尚不支持的高级 PBR 纹理/扩展会明确报错，不能静默丢失材质。
- 验收用人工断言与受控 provider 不构成模型精度验证。尚无可公布的真实推理时延、费用分布或稳定 p95。
