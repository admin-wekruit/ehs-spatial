The delivery target is one owned object identity linking source-photo evidence,
CAD and browser-visible model geometry, through the same analysis path for every
new capture. Counts, downloadable Blender files and successful GPU processes are
not acceptance of shape or correspondence.

## Reusable path and measured stage executions

Capture analysis, explicit object generation and quality review use immutable
source IDs, bytes, selected observations, provider pins and configuration. CAD
validation and model quality are evaluated independently of model availability.
An owned empty capture can prepare geometry or depth validation without already
having the outputs those stages are intended to create. Preparation does not
invoke a model or write a scene.

Runtime validation retains unverified release gates. The first Map run predates
mandatory adapter-file SHA binding; its original envelope and result remain
unchanged. Subsequent geometry/depth deployments require the exact adapter-file
SHA as well as immutable model/code/image identities, and the frozen stage hash
is checked before inference. MoGe's validation includes that adapter binding.
A changed deployment cannot silently execute a differently pinned queued input.

Generic geometry/depth dispatch now stores the original external invocation ID
in the existing model-call ledger before waiting for the result. Completion and
late results preserve that ID. A transient result-read failure remains unknown
and does not cancel the valid computation or submit another paid request. A
failed receipt transaction or lost attempt instead cancels only its newly spawned
handle on a best-effort basis, retaining unknown status and its reservation.

Both product and research paths validate returned geometry/depth contents before
reporting stage success. A matching model name or pins with an empty, foreign-grid
or invalid response fails. Hash-verified returned artifacts remain available for
diagnosis, without a second paid request merely to repeat validation.

The complete Python suite after retained-model review, CAD source selection and
shared surface/context corrections passed 1,079 tests; 29 environment-dependent
tests were skipped. This is code/transaction evidence,
not proof that a new uploaded workcell finishes with accepted models.

## Shared review and failure behavior

`review_models` reuses the same mesh/CAD/source validator as new generation. The
existing models were checked with fixed job inputs and zero new provider calls.
090 retained all original models and transforms: 16 rows are geometrically
consistent, eight are inconsistent, and all 24 lack an independent configured
shape review. 030 retained both button models and their exact quality bindings.
Reports show this as the last check, never as current physical compliance.

The viewer exposes observed CAD and current-model CAD as separate explicit
sources. Both use real mesh-triangle projection; selection remains the same
entity when switching. Public 090 and local 030 reverse CAD selection were
verified in the browser against photo, model preview, details and URL identity.
030's successful review also advanced the editable report URL to the new revision;
reload preserved the revision and selection. Published revisions remain fixed.

All source surface creation now rejects zero-area triangles after the original
edge-discontinuity filter and drops unused vertices. It does not connect sparse
origin placeholders into invented surfaces. Unsupported observations and photos
produce explicit errors while successful neighboring observations/photos remain.
Normal fresh-capture analysis and rebuild share that same context-error result;
a collapsed photo with empty discovery cannot report successful empty analysis.
Synthetic tests cover all-collapsed and mixed valid/invalid photos. They do not
substitute for the still-unfinished real fresh-photo release gate.
