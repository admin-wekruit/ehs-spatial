### Integration notes (only systems that are actually reusable in a Python pipeline)

- **Spark-DSG (BSD-2, `pip install spark-dsg`)**: container for the scene graph; keep its JSON as the canonical 3DSG and emit clingo facts from node attributes / inter-layer edges. Hydra / Khronos (BSD) only if you need to build graphs from RGB-D yourself.
- **heracles (GPL-3.0)**: a ready spark_dsg -> Neo4j loader plus Cypher tool interface; useful as a reference for the scene-graph -> query layer, but GPL means re-implement rather than vendor if the service is distributed.
- **clingo (MIT, pip)**: the rule engine; facts from the scene graph, rules from the clause KG, stable models -> verdicts; use optimisation/weak constraints or multiple models to express uncertainty.
- **AEC3PO (CC BY 4.0 via TTL)**: reuse `Document` / `DocumentSubdivision` / `Table` / `DefinitionStatement` / `CheckStatement` subclasses and the RASE `RequirementStatement` / `ApplicationStatement` / `ExceptionStatement` / `SelectionStatement` classes as the schema for the ISO/IEC/OSHA clause KG; `SHACLCheckMethod` maps naturally to pySHACL, `CompositeCheckMethod` to a clingo rule bundle.
- **CODE-ACCORD (CC BY 4.0)**: 862 annotated sentences to bootstrap an entity / relation extractor for clause text; **accord-nlp (Apache-2.0)** is the matching NER + RE notebook pipeline.
- **TUM ACC-function-generation (MIT)**: pattern for LLM-generated, reusable check functions scored against a ground-truth checker; port the loop from IFC to the scene-graph JSON.
- **nl2spec (MIT)** and **GinSign (MIT)**: NL clause -> LTL with sub-translation explanations (nl2spec) and signature-constrained grounding of atomic propositions (GinSign) - useful for the regulation-corpus side when a clause is temporal; GinSign's signature idea maps directly onto a fixed predicate vocabulary from the scene graph.
- **Logic-LM (MIT)** and **CodeAct (MIT / Apache models)**: solver-in-the-loop self-refinement pattern for LLM -> ASP translation errors (feed clingo parse / grounding errors back).
- **pySHACL (Apache-2.0)**: if the clause KG is RDF, use it for structural checks of the KG itself (and for AEC3PO `SHACLCheckMethod`), not for metric reasoning.
- **Nemo (Apache-2.0 OR MIT, `pip install nemo-python`)**: Datalog alternative to clingo when existential rules / RDF ingest matter; **Souffle (UPL)** only as compiled Datalog, no pip. **SWI-Prolog + janus (BSD-2)** if Prolog is preferred over ASP.
- **ZEN (MIT, `pip install zen-engine`)**: already a dependency; keep it for business-rule tables (thresholds, jurisdiction switches) upstream of clingo, not for spatial logic.
- **RTAMT (BSD-3, pip)**, **Reelay (MPL-2.0, pip)**, **MoonLight (Apache-2.0, Java + pip wrapper)**: temporal / spatio-temporal monitors over per-frame verdict signals; MoonLight's STREL is the only one that natively reasons over a spatial graph, which fits a scene graph with metric edges.
- **SGSM / SceneFlowLang / PerceMon**: reference designs for "scene graph + temporal property -> violation" monitoring; SGSM (MIT) is closest in spirit (LTLf over scene-graph predicates) but its GPL deps and CARLA-specific graph format mean copying the approach, not the code.
- **AWS Automated Reasoning checks**: regulation PDF -> formal policy -> VALID/INVALID findings, a drop-in for the regulation-corpus side if a managed, non-open, English-only, $0.17 per 1,000 text units service is acceptable; it does not consume scene graphs.
- **Solibri**: Java-only, proprietary, Advanced/Premium tier for custom rules; useful as a ground-truth checker for IFC (as TUM did), not as a pipeline component.

Everything else (GuardEn, I-SNACC, LLM-FuncMapper, SGR-BIM, Han et al., Zhang & El-Gohary, RieMind, P4IR, PropTest, LogiSafetyGen, DriveReg, Lawful-AD, BifrostRAG, ASG) is paper-only or an empty repo as of today and can only be re-implemented from the method description.
