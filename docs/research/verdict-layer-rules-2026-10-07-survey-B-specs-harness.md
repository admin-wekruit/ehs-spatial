Scope note: all numbers below come from vendor/regulator reproductions of the standards (ISO texts are paywalled); where a clause number or value could not be confirmed it is marked **unverified**. ## PART 2 — How verdicts are structured professionally

Chain: requirement (clause) → applicability (does the rule apply to this object/scene? ISO 12100 hazard identification decides) → measurand + method → threshold (table/formula) → evidence → verdict. ISO 12100 frames this as iterative risk assessment with the 3-step method (inherent design → safeguarding → information); ISO 13849-1 sets PLr via S1/S2, F1/F2, P1/P2 and PL a–e with PFHd bands 10⁻⁵…10⁻⁸ (Reer https://int.reersafety.com/?p=38995). Verdict vocabularies in formal practice: TTCN-3 uses `none < pass < inconc < fail < error` with a severity lattice (https://en.wikipedia.org/wiki/TTCN-3) — a good model: "inconc" = cannot determine, and an aggregate verdict is the max over sub-verdicts. Metrology adds the uncertainty-aware variant: ILAC-G8:09/2019 non-binary statements (pass / conditional pass / conditional fail / fail) with guard bands; ISO/IEC 17025 7.8.6 obliges labs to state the decision rule (UKAS LAB 48 https://ukas.com/wp-content/uploads/2023/05/LAB-48-Decision-rules-and-statements-of-conformity.pdf ; Fluke https://www.fluke.com/en-us/learn/blog/calibration-software/decision-rules-conformity-assessment : acceptance zone = tolerance − U, Type A false-accept ≤ 2%). Auditors document evidence as: clause cited, measured value, instrument/method, uncertainty, photo reference, and a signed verification table (ISO 10218-2:2025 requires integrators to verify safeguard responses and stopping distances against calculations — evsint).

Vendor tools (none checks a *photographed* layout against 13857/13854): SICK Safety Designer configures fields "on measured contours or imported layouts" and produces verification reports (https://www.sick.com/in/en/c/g575306); Pilz Safety Distance Calculator computes 13855 distances from stop time/resolution/PLr (https://www.industrial-production.de/safety---security-en/images/safety-distance-calculator-determines-safety-distances-1.htm); Pilz PAScal, Siemens TIA Safety Evaluation and Rockwell Safety Automation Builder compute PL/SIL and (Rockwell) let you draw zones on imported drawings (https://directindustry.com/prod/pilz/product-7550-1641746.html ; https://siemens.com/nl/en/products/automation/topic-areas/safety-integrated/factory-automation/support/tia-safety-evaluation-tool.html ; https://www.rockwellautomation.com/en-au/capabilities/industrial-safety-solutions/safety-automation-builder.html); ABB RobotStudio simulates braking distance to size SafeMove zones (claims up to 25% footprint reduction, https://new.abb.com/news/detail/74174/prsrl-new-braking-distance-simulator-improves-safety-and-reduces-robotic-cell-footprint-by-up-to-25-per-cent). Digital-twin/3D approaches exist mainly as patents: Veo-style 3D-sensing functional safety twin (https://patents.google.com/patent/US11675329), scan-to-twin safety-sensor placement (https://patents.google.com/patent/US11493908), "method for checking a safety area of a robot" (https://patents.google.com/patent/US11731283). Academic: laser-measured safety-distance verification driven by a digital twin (Springer 2022 https://link.springer.com/chapter/10.1007/978-3-031-10071-0_9), online distance tracker for robot safety verification (2023 https://pmc.ncbi.nlm.nih.gov/articles/PMC10057077/), VTT twin + projected safety zones (https://cris.vtt.fi/en/publications/digitaltwin-of-a-robot-cell-with-projected-ar-of-dynamic-safety-z/). Construction/BIM is the mature analogue: Zhang/Teizer rule-based fall-protection checking in Solibri (https://cris.vtt.fi/en/publications/bim-based-fall-hazard-identification-and-prevention-in-constructi/), Cloud2BIM scan→IFC (https://arxiv.org/abs/2503.11498), scan-to-BIM fire-compartment checking (https://ec-3.org/publication/ec32026_418/), TUM "Scene2Compliance" (https://cee.ed.tum.de/fileadmin/w00cbe/cms/Softwarelab/2025/14_SL2025_Description_Scene2Complaince-YonghanKim.pdf), graph-based geometry-intensive checking (https://arxiv.org/abs/2606.12065). No peer-reviewed paper was found that issues ISO 13857/13854 verdicts from photos or point clouds of robot cells — that gap is real (unverified absence).

## PART 3 — Harness / evaluation methodology

**Golden dataset.** Label per (scene, object, rule) a verdict {pass, fail, inconclusive, n/a} plus the measured value and the evidence object IDs; two annotators + adjudication. Report Cohen's κ (2 raters) or Krippendorff's α (≥2, handles missing); accept α ≥ 0.80, tentatively ≥ 0.667 (https://surgehq.ai/blog/inter-rater-reliability-metrics-an-introduction-to-krippendorffs-alpha). Size: Gwet's simulations show 95% CI coverage of κ is acceptable at n ≈ 40 items per rule for all agreement levels (https://pmc.ncbi.nlm.nih.gov/articles/PMC5965565/); for a target κ with a desired CI width use Sim & Wright / Donner-Eliasziw tables (kappaSize, https://cran.r-universe.dev/kappaSize/doc/manual.html). Practical target: ≥ 40 labelled rule-instances per rule, ≥ 10 of them fails, ≥ 5 inconclusive; ~30–60 scenes covers a 12-rule pack. Document the dataset with a datasheet (https://arxiv.org/abs/1803.09010). Metrics per rule: precision/recall on *fail* (safety-critical: recall of fail is the headline number), inconclusive rate, and a calibration plot of stated confidence vs. correctness.

**Synthetic per-rule unit tests.** Build scenes programmatically at threshold ± (ε, 2σ, 5σ): a fence at 1399/1400/1401 mm, floor gap 179/180/181, beam heights 300/600/900/1200 vs 350/650, mesh distance 199/200/201 for 40 mm mesh, crush gap 499/500/501. Property-based testing with Hypothesis (https://hypothesis.readthedocs.io/) generates random scenes and checks invariants. Metamorphic relations (Chen et al. review https://eprints.nottingham.ac.uk/51607 ; geometric MRs: GeoMetaMorph https://edoc.hu-berlin.de/18452/38724 ; GeMTest framework https://conf.researchr.org/details/icse-2025/icse-2025-demonstrations/9/GeMTest-A-General-Metamorphic-Testing-Framework): (a) rigid transform of the whole scene (SE(3)) → identical verdicts and identical measured values; (b) uniform scale change with reference re-scaled → identical; (c) moving a guard across a threshold by > 2σ flips the verdict monotonically (pass → fail, never pass → inconclusive → pass); (d) deleting an object not in any evidence list → no verdict changes; (e) duplicating an object → no change; (f) increasing uncertainty → verdicts can only move toward inconclusive, never flip pass↔fail; (g) tightening T or d → S_required monotone non-decreasing. No published MT work targets machinery-safety checkers; this is a proposal, not a citation.

**Uncertainty-aware verdicts.** Treat each measurement as value ± U (k=2) and apply a guard-banded decision rule exactly as ILAC-G8/ISO 14253-1 do: fail if value + U < threshold (clear fail), pass if value − U ≥ threshold, else `needs_measurement` (the ILAC "conditional" zone). ISO 14253-1's default guard band equals U (**unverified; not fetched**); JCGM 106:2012 gives the probabilistic form (https://www.bipm.org/documents/20126/2071204/JCGM_106_2012_E.pdf). With ±1–2 cm scale error, 13857 Table 2 entries (steps of 100 mm) and floor-gap 180 mm are decidable; 13857 Table 4 small openings (2–25 mm) and 13854 finger/hand gaps (25–100 mm) are not, and should default to needs_measurement unless the object is a known catalogue item. Object-confidence enters as applicability: below a per-class confidence threshold emit `cannot_determine(reason=object_identity)` rather than a verdict. For calibrated confidence use split-conformal prediction on the golden set (https://arxiv.org/abs/2107.07511) so that "pass at 90%" is empirically 90%.

**LLM components.** If an LLM compiles clause text into rule objects: measure entity/relation F1 against hand-written rules (Fuchs et al. 2024: GPT-3.5 few-shot on NZ Building Code → LegalRuleML reached only 53.5–60.6% F1 with random exemplars, best 71.1% with retrieved exemplars, oracle 75.4%, vs 68.4% supervised baseline — https://arxiv.org/abs/2407.21060); LLM-FuncMapper reports near-100% of computable clauses mappable to a function library (https://arxiv.org/abs/2308.08728); LLM-generated BIM check scripts: GPT-4o and Claude 3.5 Sonnet completed all rules but Gemini/Perplexity < 15% success, DeepSeek ~33%, Llama-3.1-405B and Copilot produced no working scripts (https://arxiv.org/abs/2506.20551 ; **snippet-level numbers, verify in paper**); Iversen et al. report 97% F1 regulation classification, 100% dependency identification (cited in https://avestia.com/CSEE2025_Proceedings/files/paper/ICSECT/ICSECT_182.pdf); the "Automatic Building Code Review" study found agent pipelines calling a deterministic engine (COMcheck) beat RAG reasoning for audit-ready output (https://arxiv.org/abs/2510.02634). Lesson: LLM compiles, symbolic engine decides. Harness: round-trip (rule → NL → rule) equality; differential testing of two independent compilations (McKeeman 1998, https://www.cs.swarthmore.edu/~bylvisa1/cs97/f13/Papers/DifferentialTestingForSoftware.pdf); diff of generated vs. hand-written rule executed on the synthetic grid. If an LLM is a *judge*, known biases are position bias (only GPT-4 consistent in > 60% of swapped-order cases), verbosity bias, self-enhancement (GPT-4 +10%, Claude-v1 +25% self win-rate) (Zheng et al. https://arxiv.org/abs/2306.05685), systematic position-bias study (https://arxiv.org/abs/2406.07791), and robustness failures under perturbation (https://arxiv.org/abs/2506.09443) — so never let a judge issue the verdict; use it only to triage explanations, with swapped-order double scoring.

**Regression in CI.** Version the rule pack semantically (rule_id@version, clause, edition); snapshot golden verdict JSON per scene (approval-test style, as OPA policy tests do https://www.openpolicyagent.org/docs/latest/policy-testing/); fail CI on any verdict flip; diff the `explain` text separately as a warning; re-run metamorphic suite nightly on all scenes; store evidence hashes so a re-render cannot silently change the evidence.

## (2) Verdict object schema

```
Verdict {
  rule_id, rule_version, standard, edition, clause, table_row
  rule_class: TOPOLOGY | GEOMETRY | SEMANTIC
  applicability: {applies: bool, reason, subject_ids[], hazard_ids[]}
  measurand: {name, value, unit, method, U_k2, sources: [object_ids, mesh faces/OBB edges]}
  threshold: {op, value, unit, derived_from: {inputs:{T?, d?, risk_level?}, formula}}
  unknown_inputs: [{name, needed_for, source_hint: "datasheet|config|human"}]
  decision_rule: "guard_band_U_k2" | "simple_acceptance"
  verdict: PASS | FAIL | NEEDS_MEASUREMENT | NOT_APPLICABLE | CANNOT_DETERMINE
  margin: value - threshold (signed), margin_sigma
  confidence: {object_identity, measurement, overall (calibrated)}
  evidence: [{object_id, class, class_conf, obb, floor_contact, view_ids, image_crops}]
  explain: human text; severity: PL-r-style S/F/P hint (from ISO 13849-1 risk graph, human-supplied)
  provenance: {scene_id, reconstruction_version, rule_pack_hash, timestamp}
}
```

## (3) Harness plan

- Freeze a rule-pack v1 with the 12 rules above; each rule file carries clause, URL, threshold table, unit, and uncertainty class (decidable at ±2 cm or not).
- Synthetic scene generator (parametric fence/robot/e-stop/aisle) producing threshold-grid cases (±ε, ±2σ, ±5σ) for every numeric rule; these are the unit tests.
- Hypothesis property suite: SE(3) invariance, scale-with-reference invariance, irrelevant-object deletion, duplication, uncertainty monotonicity, threshold monotonicity.
- Golden set: ≥ 40 labelled instances per rule (≥ 10 fails), double-annotated, α ≥ 0.80 required before use; adjudicated labels with evidence IDs.
