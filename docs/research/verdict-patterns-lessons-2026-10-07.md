# 别人怎么做"理解表示 + 规则判定"，我们能学什么（2026-10-07）

问题（用户）：我们的理解 pattern（场景表示）和规则判定，别人是怎么做的，能学什么？场景图到底帮不帮助理解和解释？

## 0. 我们的 pattern，一行一级

| 级 | 我们今天 | 产出 | 已知弱点 |
|---|---|---|---|
| 感知 | SAM 3 掩码 → MVS + MoGe-3 几何 → SAM 3D 补全 → 组装 v2（地面接触） | 每个对象：网格、有向盒、尺寸、离地高、每维 σ（部分）、置信度、每面被哪些照片看到；急停参照定尺度 | low 置信度盒没有 σ；没有"观察范围"；机器人只是姿态盒 |
| 表示 | 薄场景图（2026-10-07 晚）：对象节点 + 类型化米制边（3D 最近距离、水平距离、离地缝、z 重叠、above、越过三元组、视线）+ 平面占用格；可导出 Spark-DSG | `scene-graph.json`、`.dsg.json` | places 层 observed = unknown；没有 zone 节点（危险区 / 操作位 / 通道） |
| 规则 | 封闭词表；LLM 只把条文编译成规则并可拒绝（8 月机制）；试跑 clingo 规则包 v0（5 条） | `rules.lp`，阈值当事实 | 词表要等 safety specs 定；表 2 等查表值未对正文核 |
| 判定 | 护带决策：V ± U 整体在一侧才选边；PASS / FAIL / NEEDS_MEASUREMENT / NEEDS_INPUT / CANNOT_DETERMINE；适用性由审核员断言 | `verdicts.json/.md` | U 用默认值的地方多；适用性机制还没接到新引擎 |
| 解释 | 判定引用边（值、U、端点、照片）；平面图 / 立体图；"为什么"由 Gemini 引用 fact id（8 月 POC） | 表、图 | 没有度量过"审核员能否一分钟追到证据" |
| harness | 63 个单元测试 + 合成场景基准（间距一族）+ 编译器考试（13 条 OSHA） | — | 没有真实金标集、拓扑 / 语义规则测试、蜕变测试 |

## 1. 九个领域的案例（浓缩；全文和每条链接在附录 C `verdict-patterns-lessons-2026-10-07-survey-C-cases.md`）

| 领域 | 表示 | 规则 / 判定 | 它们学到的 | 给我们的一句话 |
|---|---|---|---|---|
| **BIM 规范检查**（Solibri、Eastman 2009、buildingSMART IDS、EU ACCORD、I-SNACC） | IFC 对象模型；IDS 把每条规则拆成"适用对象（6 种 facet）+ 要求" | Solibri 50+ 参数化模板，用户只填参数不写逻辑，严重度按偏离量自动算，人标 accept / reject；ACCORD 用 RASE 标条文编成 SHACL；I-SNACC（NLP → 逻辑）IBC 第 10 章 P 95.2 % / R 100 % | 15 年后瓶颈不是执行是**解释条文**：Zou 2023 访谈 20 位专家，技术变量里有"统一的条文解释方式"；翻译 + QC 一页条文约一个专家日；条文更新频繁；Solibri 用户抱怨陈旧 / 错误结果 | 我们的"LLM 编译、不能表达就拒绝"就是那个瓶颈本身，要当产品做：条款对齐、IDS 式显式适用性、版本化、QC |
| **工地照片识危**（Fang 2020 CV + 本体知识图谱；Zhang/Teizer 2015 本体；2023–2025 场景图 + 法规三元组匹配，PPE F1 0.84） | 检测 → 知识图谱 / 场景图 | 本体 + SWRL 推理 | (i) 感知错误直接传进规则；(ii) OWL/SWRL 开放世界，"没检测到安全帽"推不出"没戴"，要显式闭包；(iii) 规则手写、自建数据集，没有部署报告 | 缺失必须是一等值：缺一条边 → NEEDS_INPUT / CANNOT_DETERMINE，永远不是静默 PASS；检测器召回率进证据链 |
| **自动驾驶**（Mobileye RSS；Maierhofer / Esterle 形式化交通法规；PerceMon / STPL 感知监控；SGSM → Scene Flow Specs → Abstract Scene Graphs；ISO 21448 SOTIF） | 抽象场景 + 跨时间持久的实体身份 | 安全距离公式（RSS），时序逻辑；感知输出本身也有规约（对象持久性、分类一致性、空间关系） | RSS 把感知放在规则外面，靠冗余和 PAC 感知模型；批评者说感知假设不足，提出"不精确世界模型"：判定必须对所有与感知置信度相容的世界成立；FSE 2025 发现纯场景图写不了时序性质，加了持久实体；SOTIF 把"未知-不安全"当一等公民 | 规则写在带持久身份的抽象场景上；给感知层单独的规约；显式的"未知"类；遗漏不等于安全 |
| **机器人 3D 场景图**（Hydra、Clio、ConceptGraphs、SayPlan；MIT 2025 "Structured Interfaces"） | 分层场景图 | LLM 查询 / 规划 | 最干净的消融：给 LLM 一个 Cypher 查询工具比把图塞进上下文好、比代码生成好，省 token、可扩展——但度量的是任务成功率，从来不是人的可解释性；3DSSG 谓词 R@3 0.89 但三元组 R@50 只有 0.40；GQA 上真值场景图 94.6 % vs 生成场景图 52.9 % | 图靠"可查询、带来源的接口"挣饭吃，不是靠"理解"；学出来的分类谓词会垮，几何算出来的米制关系（我们的距离 / 缝 / 占用）才活得下来 |
| **神经符号视觉推理**（NS-VQA、VisProg、ViperGPT、Logic-LM） | 感知出符号 / 程序 | 符号执行器 | NS-VQA CLEVR 99.8 % 且每步可查；Logic-LM 报告**可执行编译率**（GPT-4：合成集 99–100 %，FOLIO 79.9 %，AR-LSAT 32.6 %），不可解析的回退到 CoT，把求解器错误喂回去提升约 5 点；大部分错误在视觉模块不在程序 | 把"条文 → 规则编译率"当 KPI 发布；不可编译的桶显式保留，不做软回退；预期符号 / 感知错误占主导 |
| **法律工程 / Rules as Code**（Catala、OpenFisca、NZ Better Rules、加拿大 RaC、OECD、LegalRuleML） | 默认逻辑一等公民（基础规则 + 例外写在条文写例外的地方），代码与条文逐段对齐 | Catala 编译器在 F* 里证明，还抓到法国官方福利实现的 bug；CUTECat 生成覆盖所有分支的测试；OpenFisca 每个参数带生效日期和法律出处 | 多学科团队"强迫概念一致"，暴露隐藏假设；"解释含义"是最难的；命令式代码装不下整部法；OECD 要求可追溯、可问责、**可申诉** | 规则包是法律工件：条款对齐、可废止、带日期、测试覆盖、领域专家签字、可被推翻——判定要带"什么证据能推翻我" |
| **临床决策支持**（Arden Syntax、GLIF、PROforma、HL7 CQL / CDS Hooks；几十年经验） | 事件-条件-动作规则；站点数据绑定（"花括号问题"）导致规则不可移植 | **三值逻辑**：Arden 有 null 类型，CQL 为"缺失信息下推理"定义 3VL，CDS Hooks 禁止用占位符冒充 null | 形式化必然暴露规范缺陷（决策表分析发现不完整 / 不一致；Asbru 异常检测发现歧义和遗漏）；部署现实：告警覆盖率 46–96 %，原因是特异性低；知识获取瓶颈从 1977 到 2017 综述都是第一问题 | 把"未知"传过每个算子并显式输出"数据不足"；让用户不再看的是假阳性不是漏报；编译器发现的每个歧义都回给 spec 的主人 |
| **工业 / 功能安全实践**（ISO 12100、ISO 13849-1、SISTEMA、PAScal、SICK Safety Designer、ISO 13855:2024、ISO 13857:2019；数字孪生论文 / 专利） | 人主导、有文档的风险评估 | 每个工具只算一个窄量，模型外的拒绝算：SISTEMA 的 PLr 由工程师输入，简化法只适用于指定架构；S = K·T + C 的 K、T、C 是声明输入 | 从 3D 数据自动验证防护很薄：Seim 2022 用数字孪生生成激光测量程序但点位还是安全工程师选；在线距离跟踪只在静态仿真里；专利有，没有已部署的照片防护验证器（未证实的缺席） | 声明输入保持声明：停止时间、接近速度、PLr、参照物尺寸是 NEEDS_INPUT，永远不从照片推 |
| **计量合格判定**（ISO/IEC 17025、ILAC-G8:09/2019、ISO 14253-1、JCGM 106、UKAS LAB 48） | 值 ± U | 容差限、接受限、护带 w；四态陈述：pass（w = U 时误接受约 2.5 %）、conditional pass（护带内，风险可到 50 %）、conditional fail、fail；JCGM 106 分"这一件的风险"和"全局风险" | 17025 要求声明决策规则；UKAS 给报告措辞 | 四态陈述原样采用；每条判定印决策规则和 U；"conditional" 是独立状态不是四舍五入 |

## 2. 跨领域反复出现的模式

| 模式 | 谁在用 | 买到什么 | 代价 |
|---|---|---|---|
| 感知与规则之间的封闭词表 | IDS facets；AEC3PO/SHACL；STPL / 场景图监控；CQL value sets | 规则可检查"能不能表达"；感知可以单独规约和测试 | 每个新谓词是一次 schema 变更；开放词表检测器要映射 |
| 显式"未知 / 数据不足"状态 | Arden/CQL 三值逻辑；ILAC conditional；SOTIF unknown-unsafe；SISTEMA "不适用" | 杜绝靠遗漏得到的静默 PASS；缺口可行动 | 判定类别变多，用户要接受"我们不知道" |
| 规则对齐条款并带测试 | Catala、LegalRuleML 同构、RASE、OpenFisca 出处、CUTECat | 可审计、可签字、标准改版时便宜地重验 | 条款级编写成本（约一个专家日 / 页） |
| 符号执行器 + ML 感知，ML 永不当裁判 | NS-VQA、VisProg/ViperGPT、Logic-LM、I-SNACC、SGSM | 确定性、可检查的判定；错误可归到模块 | 编译率有上限（真实文本 33–80 %）；对符号错误脆弱 |
| 解释 = 证据链 | Solibri issues + BCF；CDS 告警理由；NS-VQA trace；Safety Designer 文档 | 用户能质疑判定；假阳性可分流 | 要存每一步的来源，不只是结果 |
| 版本化规则包 | OpenFisca 带日期参数；LegalRuleML 时效；SISTEMA 按 ISO 版本 1.x/2.x/3.x | 判定对某个标准版本可复现 | 每版都要迁移和回归 |
| 带不确定度的阈值 | ILAC-G8 护带；JCGM 106；RSS 参数界 | 临界处诚实；风险有数 | 每个测量要有可信的 U，否则护带是虚构 |
| 人工适用性签字 | IDS applicability；ISO 12100；SISTEMA 的 PLr；RaC 可申诉 | 范围错误在规则跑之前被抓住 | 全自动变慢；要一个"这条规则为何适用"的 UI |

反复出现的失败：**知识获取瓶颈**（从 Feigenbaum 1977 到 Zou 2023，贵的是解释规范不是执行）；**感知错误传播**（GQA 94.6 → 52.9，3DSSG 三元组 0.40）；**开放 / 闭合世界混淆**（OWL 推不出"缺 PPE"，AD 监控被迫加实体持久性）；**规则漂移**（规范改版）；**无用户的过度形式化**（六种临床指南模型无共识，ACC 原型几十年低采用）；**声称可解释但从不度量**（VisProg / 场景图规划只度量任务成功率；告警疲劳数据说明没度量的解释在实践中的下场）。

## 3. 场景图帮不帮助理解——证据怎么说

帮，但作为**接口和证据底座**，不是作为理解。图带来收益的地方都来自检索和规模（SayPlan 的折叠图搜索；MIT 2025 的 Cypher 接口胜过上下文序列化）或来自"把规约写在稳定的语义空间上而不是像素上"（SGSM → Scene Flow → ASG）。让图自己**供给**语义的地方都不行：预测谓词是 3DSSG 里最差的数，也是生成场景图在 GQA 上掉 40 分的原因。
对我们是好消息：我们的边是重建算出来的米制量（距离、缝、重叠、视线、占用），不是学出来的谓词，所以图是"带不确定度的、可查询的测量台账"——AD 和机器人的结果支持的正是这个角色。保持薄；不加学出来的关系类；暴露成查询接口（Spark-DSG 导出和 MIT 的发现一致）。

## 4. 给我们的 12 条（按优先级，每条对应案例和我们流水线的级）

| # | 教训 | 来自 | 落到我们哪一级 / 怎么做 |
|---|---|---|---|
| 1 | 计量式判定：值 ± U、决策规则、护带、四态陈述；NEEDS_MEASUREMENT 就是 conditional | 计量 | 判定级：试跑已按护带做；报告上印决策规则和 U |
| 2 | 缺失是值：三值逻辑传过每个关系；缺对象 / 缺边 → NEEDS_INPUT / CANNOT_DETERMINE，永不 PASS | 工地、临床 | 规则级：clingo 失败即否定已天然如此；要把"规则需要的事实"声明化 |
| 3 | 规则包是产品：条款对齐、RASE 适用性 / 例外标注、按标准版本带日期、带测试；预算约一个专家日 / 页 | BIM、法律 | 规则级：specs 来了按此做；每条规则文件带条款、版本、测试 |
| 4 | 发布编译率：条文被编译 / 拒绝 / 需人工修的比例；拒绝桶是功能 | 神经符号 | harness：编译器考试进 CI，报三个数 |
| 5 | 声明输入保持声明：T、接近速度、PLr、参照物尺寸是 NEEDS_INPUT，不从照片推 | 功能安全 | 规则级：reach_over / 13855 规则已这样做 |
| 6 | 给感知层单独的规约（STPL 式）：跨视角对象持久性、尺寸一致性、地面接触，在规则跑之前检查 | AD | 感知级：我们的 workcell_layer_trial 检查（shape / floor / lines / plane_stereo / obvious_errors）就是雏形，要形式化成"感知规约" |
| 7 | 显式适用性签字：人先确认哪些规则适用于这个工位 | BIM、功能安全 | 判定级：平台的 policy_applicability 注释保留，接到新引擎 |
| 8 | 每条判定的证据链：照片裁图、网格 / 盒、测量值、U、条款、规则版本，足以申诉 | BIM、临床、RaC | 解释级：Verdict schema（D7）已有这些字段，报告要渲染 |
| 9 | FAIL 的精确率优先于召回：低特异性告警让用户不再看；宁可 CANNOT_DETERMINE 不要投机的 FAIL | 临床 | 判定级：护带 + 适用性签字；harness 指标里加 FAIL 精确率门槛 |
| 10 | 图保持薄、可查询：只放米制关系；提供查询 API；别让图变成"理解" | 机器人 | 表示级：现状正确；下一步是查询接口不是更多层 |
| 11 | 跟踪"未知-不安全"：词表之外的情况记成 SOTIF 式 backlog，不是静默超范围 | AD | 规则级：编译器拒绝的条文 + 场景里无法归类的对象 → backlog 文件 |
| 12 | 形式化会发现规范 bug：Catala 和临床指南验证都抓到官方文本的错；回给 spec 作者，不写进规则 | 法律、临床 | 规则级：specs 的歧义列表作为交付物之一 |

## 5. 预训练 / 后训练能不能替代这一套（浓缩；全文和链接在附录 D `verdict-patterns-lessons-2026-10-07-survey-D-training.md`）

**短答案**：有人在做端到端的 3D/4D 空间理解，2025–26 也有几篇"学出来的合规判定"，但没有一个达到厘米级米制可靠性，没有一个天生带审计链；
2026 年空间基准上最好的两个结果反而来自**把显式 3D 场景图 + 几何工具放在 LLM 下面**，不是端到端训练。

| 路线 | 代表 | 数字 | 止步在哪 |
|---|---|---|---|
| 3D 视觉语言模型（预训练 / 指令微调） | 3D-LLM、LEO、SceneVerse（68K 场景、250 万对，文本多半**从场景图模板生成**）、Chat-Scene、LLaVA-3D、Video-3D LLM、VLM-3R（VSI-Bench 60.9）、Spatial-MLLM（48.4） | ScanQA / SQA3D 分数逐年涨 | 基准失效：ACL 2025 发现把点云渲染成图喂 2D VLM 就能赢；ICLR 2026 发现**纯文本**微调模型在 SQA3D 上持平或胜过 3D-LLM；3DSSG 上关系 R@50 只有 29–31 %，"hanging on / attached to / supported by" 系统性混淆 → **学出来的谓词不可靠，算出来的几何谓词可靠** |
| VLM 空间推理后训练 | SpatialVLM（20 亿合成问答；"在真值 0.5–2 倍内"算对，37 %，GPT-4V 0 %）、SpatialRGPT（±25 % 内算对：直接距离 35 %，定性关系 92 %）、Multi-SpatialMLLM（2700 万样本，定性 80–90 %，定量仍低）、RLVR 一族（SpaceR、ViLaSR、SpatialLadder、SVQA-R1）、Cambrian-S（VSI-Bench 67.5）、SenseNova-SI（68.8） | VSI-Bench：人 79 %，Gemini-1.5 Pro 45 %，绝对距离 31 %（接近随机）；71 % 的错误在空间推理 | 成功标准是"±25 %"或"2 倍内"，不是厘米；Cambrian-S 视频自拼接后 42 % → 0 %，词袋基线在 VSI-Super-Recall 拿 95 %；全部室内家居 / 办公数据，不是工厂；每个模型 12 万–2700 万样本，我们有 2–10 个工位 |
| 2026 反例 | RieMind（2026-03）：LLM + 显式 3D 场景图 + 几何工具（尺寸、距离、位姿），不微调 | VSI-Bench 静态任务比先前最好 +16 %，比基础 VLM +33–50 % | **显式几何胜过端到端** |
| 指点 / 框 | Molmo（230 万人工点，点后计数 91 %）、Gemini Robotics-ER 1.5 / 1.6（指点、2D 框、仪表读数 93 %） | 强 | 没有可审计的米制数字 |
| 4D | 符号的：Khronos、DovSG、ST-OVSG、Aion、WSGG（都为导航 / 操作）；学的视频场景图：Action Genome SGDET R@20 ≈ 40 %，PVSG R@20 3.9 %；世界模型 V-JEPA 2 / Cosmos / Genie 3 为预测 / 生成训练 | 世界模型用于监控的方式只有"异常分数 + 保形阈值"（仪表巡检 > 90 %） | 没有人从世界模型出合规判定；NVIDIA 自己的仓库安全蓝图是传统 CV 产事件、Cosmos Reason 事后解说 |

**结论和我们该做的**
- 训练能买到：开放词表检测、定位、指点、计数（~90 %）、定性关系（92 %）。买不到：米制可靠性（领域自己的合格线是 ±25 %）、可审计性（三份 2025–26 的批评都证明分数来自语言 / 2D 捷径）、对工厂分布的迁移、我们这点数据。
- 成熟团队收敛的架构：基础模型产**带不确定度的符号** → 符号层判定 → 解释 = 证据链。我们现在就是这个架构。
- 2–10 个工位能后训练的只有符号生产者（都有可度量的真值）：① 检测 / 分割对受管类别的适配（护栏、光幕、急停、机器人底座）；② 米制尺度标定——是流程不是模型，这才是从 ±25 % 到厘米的那一步；③ 谓词层只算几何，若学也只在几何特征上学小分类器并报每谓词召回；④ 规则编译器（P4IR / LLASP / ARc 的模式，按条款做单元测试，输出带条款 id）；⑤ 类别链接器：VLM 提议受管类别 + 置信度，人确认，精确率够了再自动。
- 不要训练 照片 → 判定：比我们容易得多的家居危险任务 SOTA 才 F1 34.7，数字输出走捷径，没有证据链和 OOD 说法。
- 时间轴：预 / 后训练只用于动态符号生产者（跟踪、位姿 / 关键点、变化检测，世界模型做异常先验）；判定仍是符号的——每帧场景图上的时序逻辑（"机器人速度 > v 时分离距离 ≥ S_p"，ISO 34502 → STL 有先例）。4D 场景图（Khronos、Aion）是长期状态的容器。
- 什么时候重新评估端到端：等没有捷径的基准（Real-3DQA、ReVSI）在工厂类 OOD 场景上显示厘米级米制可靠性。
