# 快速版：30 秒视频，2–3 分钟出报告（2026-09-28）

**来源：**4 路调研、1 份方案、1 轮对抗式挑错（原文在 scratchpad：speed-dossier.md、speed-plan.md、speed-crit.json）。

**用户已定：**
- 演示方式：现场上传视频，等 2–3 分钟出结果。
- 算力：可以用两块 A100。
- 预算：先不管。
- 能用 GPU 就用 GPU，全部放到 Modal。
- 演示可以用研究许可的模型，比如 DA3-GIANT，但要标注出来。

**标注：**[P] 是我们自己实测的，[S] 是来源实测的，[C] 是厂商或作者的说法，[E] 是估计。

## 1. 为什么现在要 2–3 小时（都对过代码）

| 原因 | 证据 |
|---|---|
| GPU 步骤一次只跑一个 | `store.py:619` 规定付费阶段一次只跑一个 |
| 每个应用只开一台机器 | `max_containers=1`，共 8 个应用 |
| 机器随用随关 | 空闲 2 秒就关；DA3 墙钟 72 s，真正计算只有 10–15 s [E] |
| 帧太多 | SAM 2 约 290 帧，每帧 1024 个提示点；人物跟踪 30 fps 全帧跑 |
| 重 CPU 活放在 Mac 上 | 物体图 12 min、导入 13 min，还有融合和贴图 |
| 物体模型逐个生成、逐个重试 | SAM 3D 38 min；RecGen 1–3 h，强制串行 |
| 泼溅要训练 | 60k 步，20–25 min |

## 2. 目标架构

```
浏览器上传 MP4 → Modal 常驻双卡容器 (A100-80GB x2, min_containers=1, 权重常驻)
  CPU: 解码 → 切点(detect_shot_cuts) → 每个镜头选关键帧(相机动了/画面变了才选; 几何 ~5 fps, 物体 ~2 fps)
  GPU A: DA3 any-view(每个镜头一次) → GPU TSDF 融合 + 点云 → 物体掩码抬到 3D(GPU) → SAM 3D 快速模式(优先物体)
  GPU B: SAM 3 {人, 地面} + EHS 词表检测 → 关键帧之间用几何投影/SAM 2 视频传播补掩码 → Qwen3-VL 事件 → 泼溅
  写入: 容器直接写云端存储 + 云数据库, 按"补丁"追加图层; 查看器边收边显示
  后台(同一份报告继续补): 其余物体模型、30 fps 人/移动物跟踪、贴图补洞、LingBot 稠密点、完整泼溅、镜头闸门
```

## 3. 时间线

从视频进入容器开始计，热启动，全部是估计值 [E]；挑错后的现实值写在括号里。

| 时间 | 能看到 |
|---|---|
| 40–60 s（现实 60–100 s） | 相机轨迹、房间网格、点云、人和轨迹；尺度标为"待核" |
| 60–90 s（现实 90–150 s） | 物体框加名字 |
| 120–200 s | 事件，前几个完整模型（1–12 个） |
| 180–260 s | 快速泼溅 |
| 另加 | 上传 10–25 s，打开查看器 10–30 s；冷启动再多 60–120 s |

## 4. 各层怎么提速，你关心的几点

- **相机和深度：**
  - 用 DA3 一次前馈，同时出位姿和深度，替代 DROID + DA3 posed 这两步。
  - 每个镜头单独跑一次：三段视频都有切点，跨镜头一起跑的位姿没有意义。
  - 原来的可信轨迹规则继续保留。
- **SAM 2 / 分割提速（你说的缓存）：**
  - 相邻帧几乎一样的只算一次：只在关键帧上做完整分割。
  - 中间的帧用已知的相机和深度做几何投影，基本不花算力；或者用 SAM 2 视频模式传播掩码，它会复用前面帧的记忆。
  - 同一帧里图像只编码一次，提示点整批送进去。
  - 同一段视频重复跑，直接命中按内容寻址的缓存（现在已经有）。
- **物体：**
  - SAM 3 按词表批量检测。
  - 掩码抬到 3D、合并、拟合框，都放到 GPU 上做。
  - 名字请求全部并发发出。
- **泼溅：**
  - 泼溅不是 LingBot，也不是网格，是逐场景优化出来的照片级表示，所以需要"训练"。
  - 快速版先练 5k 步，约 75–125 s [E]；同时测一个一次前馈出泼溅的方法，看质量能不能接受。
- **完整模型：**
  - SAM 3D 打开快速模式，优先做 EHS 相关物体，前 3 分钟出 1–12 个 [E]，其余在后台补。
  - RecGen 只留在研究档。
- **LingBot：**
  - 不进 3 分钟的主路径，放到后台 3–6 分钟后补上 [E]。
  - 它提供三样东西：稠密细节点、对融合结果的独立交叉检验、推测地面的验证。
  - 所以 3 分钟版里没有推测地面，稠密细节少一些。
- **导入和发布：**
  - 不再用本机 Postgres 加 `modal deploy` 的方式，改成容器直接写云端、按补丁追加。
  - 这是工程量最大的一项（挑错时列为阻断项）。
  - 发布的对外快照照旧保留，用于分享和审计。

## 5. 比完整版差在哪（演示时要说清楚）

- **相机：**没有全局优化。公开数据上前馈方法 ATE 0.087 m，DROID 0.038 m [S]，可能出现双层墙。
- **房间：**3 cm 网格加顶点色，墙面发糊，洞要等后台补。
- **物体：**关键帧加约 20 个词。词表以外的、小的、只出现几帧的物体会漏；细长物体用框表示不好。
- **人：**5 fps 检测，轨迹更粗。叉车这类非人移动物要靠后台的运动跟踪。
- **泼溅：**少练的话，公开数据上低约 1.7 dB [S]。
- **尺度：**镜头闸门跑完之前不写米制结论。

## 7. 验证实验（先测再搭，全部在 Modal 上跑 ME340）

| # | 测什么 | 通过标准 |
|---|---|---|
| E1 | DA3-GIANT / DA3-BASE 按镜头 any-view：耗时、显存；位姿与 DROID 的一致度；留出视角的深度误差 | 前向 ≤20 s；一致度不差于 DROID 的 1.5 倍 |
| E2 | SAM 3 批处理：速度，以及对今天已命名物体的召回 | 2 类 ≤0.15 s/帧，20 词 ≤0.7 s/帧；召回 ≥80% |
| E3 | 5 fps 人轨迹对比今天的轨迹；SAM 3.1 stride 3 热跑速度；非人移动物的覆盖 | 路径差 ≤0.3 m；规则结论一致 |
| E4 | SAM 3D 快速模式跑 30 个物体：每次耗时、闸门通过率；每卡 1 个还是 2 个进程（MPS） | 每次 ≤5 s；通过率下降 ≤5 个百分点 |
| E5 | gsplat 5k / 7k 步的耗时和 PSNR；一次前馈出泼溅的候选方法；Qwen3-VL 用 vLLM 生成事件；双卡容器冷启动 | 泼溅 ≤125 s；事件 ≤40 s；冷启动记秒数 |
| E6 | SAM 2 只做关键帧 + 投影/传播，对比逐帧结果：耗时，以及掩码一致度（你的缓存想法） | 耗时降 5 倍以上；一致度 ≥0.85 IoU |
| E7 | GPU 版 TSDF 和物体抬升在 DA3 输出上的速度 | 融合 ≤10 s，抬升 ≤10 s |
| E8 | 导入那 13 分钟花在哪（剖析）；云端直接写入的原型 | 找到瓶颈；原型写一层 ≤10 s |

预计 A100 约 80–100 分钟，花费约 $5–10 [E]，在 m3 预留的 $20 以内。

## 8. 搭建顺序（实验通过后）

1. **双卡常驻容器骨架：**解码 → 切点 → 关键帧 → DA3 → GPU 融合 → 云端写入 → 查看器看到第一版（目标 60–100 s）。
2. 人和物体：SAM 3 + 投影 + GPU 抬升 + 并发命名（目标 90–150 s）。
3. SAM 3D 快速模式、事件、快速泼溅（目标 ≤260 s）。
4. 后台补层：其余模型、LingBot、完整泼溅、贴图补洞、镜头闸门，都往同一份报告里补。
5. **验收：**三段视频（ME340、Sam's Club、Walmart）各跑一次上传，每段都在 3 分钟左右出第一版，全程无人工；和完整版逐项对比写清楚差距。
