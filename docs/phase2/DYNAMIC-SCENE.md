# Phase 2：静态场景与带时间的人、物体模型

日期：2026-09-17。状态：**方案，尚未实现或通过动态视频验收**。这是[视频到可编辑空间计划](../algorithms/2026-09-17-video-full-scene-plan.md)的人与动态物体扩展。首轮使用现成预训练模型和几何计算，不进行基础模型训练或逐场景训练。

当前主路线与执行顺序见[统一技术路线](TECHNICAL-ROADMAP.md)。本页维护运动定义、时间状态与详细验收；旧二维入口只能复用经过审计的输入/来源，不能把其固定机位地面投影沿用到移动相机。

目标是在同一个场景坐标与时间轴上回放：结构保持稳定，人有可选择的身体模型和动作，**所有运动对象，包括车辆、搬运车、机器人和家具，都保留各自的模型、身份与运动状态**，交互结果可回到原视频核对。动态区域从静态融合中排除后，仍进入对象模型与运动链；不能只删掉它们交付空场景，也不能把所有姿态、位置融合成一张网格。

## 当前执行优先级：先完成运动定义与房间地图记忆

**下一步先核验并复用已有二维人/物跟踪代码入口，建立可靠的房间坐标、地图记忆与对象时间状态。** 代码入口存在不等于当前服务可用或真实人物视频已通过验证；本次没有已验证的人体骨骼、人体网格或移动相机下的房间坐标人体轨迹。下列顺序均为待实现/待验收；人体姿态方案调研可以并行，精细姿态、动作解释和交互事件的实现放在基础通过之后。

1. **房间地图。** 按原计划验证连续相机位姿、回环优化、地图保存/重载和再次进入房间的重定位。跨次视频必须通过真实匹配回到同一地图，不能分别对齐两套结果后声称有地图记忆；地图单位与尺度证据同时保存。
2. **实体与时间状态。** 先用真实人物片段核验现有代码的二维 ID、掩码和时间对应，通过后将其输出连接房间地图中的稳定实体；未通过就保留未验证状态。每次有效观测保存相机与对象世界位姿、可见性、关联证据和不确定性；没有足够三维依据时保留二维观测及三维未知。稳定实体对应可复用模型，位姿随时间变化，不因移动重建一个新的实体。
3. **运动定义。** 先补偿相机自身运动，再判断对象世界位姿的变化是否持续超过估计不确定性，并由多次连续有效观测支持；位置或旋转均可构成运动。暂时静止需要足够观测支持位姿一致，失跟、遮挡、关联不明或误差无法界定时为未知。禁止用某个任意写死的速度阈值、图像位移或类别直接决定运动。关节对象后续还需判断部件/关节变化，基座不动不代表整机不动。
4. **基础通过后再接模型细化、精细人体姿态与交互。** 保留所有运动对象的模型和动作这一最终要求，先完成各实体的身份、位姿时间线及地图复用；随后完善人体姿态、机器人关节、模型细节和对应事件。

`static_now / moving / unknown` 是随时间变化的观测状态；`potential_mobility` 是对象可能运动的属性，两者独立于是否拥有独立模型。单帧不动不能证明永久静态；可能移动也不证明当前正在动。地图尺度未经独立核验时，变化量只能使用已注明的地图单位，**不能宣称米制速度或输出 m/s**。

## 完整目标的表示与处理顺序

静态场景保留观测支持的墙、地面等结构；人和可移动对象作为独立实体。**静止是时间状态，不是永久类别**：停着的车、暂未启动的机器人、未被搬动的家具之后都可能运动。不能只按预设类别判断运动或决定哪些对象值得保留。对象即使暂时静止，已有独立身份和模型也不应被焊进背景；类别未识别的运动对象保留身份、观测与待建模状态，不能作为噪声删除。被遮住而从未看到的背景仍是未知表面。

| 实体 | 目标模型 | 时间变化 |
|---|---|---|
| 人 | 建立并复用同一骨架/简单身体模型，保存尺寸与定位依据；足以回放走动、坐下、伸手等可见姿态 | 同一 `entity_id` 的根位置、身体姿态、关节、可见性、状态 |
| 车辆、搬运车、椅子、箱子等刚体 | 在自身坐标中首次建立独立观测模型/粗模型；新增视角提供新表面时才补充几何 | `T_world_object(t)` 驱动已有模型；移动前后保留同一身份及各位置的有效时间 |
| 关节式机器人及带运动部件的对象 | 可复用的连杆/部件几何及关节结构；需要表达的车轮、机械臂等运动部件也按此处理 | 基座 `T_world_object(t)` 加各关节状态 `q(t)`；基座固定也可有部件运动，不能把整机视作一个固定刚体 |
| 非刚性物体 | 逐时间观测的表面/点及形变状态 | 不把变化形状套进单一刚体变换 |

动态模型交付是“可复用几何＋随时间变化的位姿/关节/形变状态”，不要求每帧重新生成完整 4D 网格。人体使用同一身体加姿态变化；刚体使用同一模型加刚体变换；关节对象更新部件关系。后续人体建模先用表达空间占用和动作的简单身体，不包含照片级皮肤、衣服、面部或个人化数字人。简单身体几何的厚度若只有假设，必须写入来源和不确定性，不能作为精确碰撞外形。下面的分割传播、精细姿态及事件步骤是后续接口安排，当前以本页最上方的地图和时间状态为执行顺序。

1. **保留连续视频与真实时间。** 复用顺序解码、帧号、时间戳、原图及哈希记录。运动跟踪消费连续帧；几何可选关键帧，不能把均匀抽出的 32 帧当成完整运动过程。
2. **掩码与相机运动共同核验。** 复用已有分割入口，拟接 SAM2 官方视频传播生成对象 masklet；以符合静态几何的对应点估计相机轨迹，再比较观测运动与相机运动所预测的重投影。光流幅度、掩码中心移动或“人/椅子”类别都不能单独证明独立运动。遮挡、深度误差和失跟要与运动分开记录；不一致区域既不能参与静态定位，也不能参与静态融合。不能只在 TSDF 最后一步遮掉它，留下已经被污染的相机轨迹。
3. **连续身份与观测分开。** 在可见段传播同一人/物的 ID，所有掩码与人体关节绑定此 ID。现有 ByteTrack 是可复用的二维关联组件；SAM2 的传播 ID 同样需要验证，均不等于跨遮挡身份真值。遮挡后匹配证据不足时保留待关联状态，不凭外观相似强行拼接，也不把未观察到的位置继续当作实测位置。
4. **同一坐标中的身体与对象。** 地图与运动状态通过后，人体关节可验证现成 MediaPipe Pose Landmarker；它的 `WorldLandmarks` 以髋部中点为原点，不能直接当房间坐标。必须结合相机位姿、对齐的深度/几何与独立尺度依据定位人体根部，再检验关节在源视频中的投影。不能默认人高或相机高度来补米制尺度，也不能把抬起的手投到地板上。刚体观测变换到对象自身坐标累计，显示时使用当时对象位姿；椅子搬走后旧位置结束占用，不留下第二把椅子。
5. **同时间计算交互并回放。** 这是地图、实体时间状态和所需身体/部件几何通过后的工作。每次取同一时间支持的人体和对象状态，计算定义明确的距离、区域进入/离开和持续时间；对象间事件也使用同样的时间约束。先实现可复核的几何事件；例如“人与车体距离进入设定范围”或“身体指定部位进入指定区域”。进入规则必须写明参与部位/体积及区域定义；机器人使用当时各连杆的位置，不能用基座位置代替运动机械臂。手靠近物体、人物与物体同步移动只是观测线索，不能自动升级为抓取、操作机器或安全/违规结论。接触、搬运等语义需要对应动作与物体状态证据；只有接近证据时只报告接近。
6. **保存后按时间读取。** 原视频、静态模型、人体骨架/简单身体、对象模型和事件使用同一地图 revision、同一时间轴与实体 ID。回环更新相机后重算受影响位姿、几何及事件，旧证据不可混入新版本；报告读取不能临时触发推理。

单目 RGB 的动态深度、尺度与三维运动存在歧义。模型给出二维跟踪或人体相对三维关节，不代表已得到准确房间坐标。缺少有效深度、尺度、相机跟踪、身份或可见性时，相应三维位置/距离/事件保存为未知及原因；显示原视频证据和状态，不用插值冒充观测。

## 关键帧怎样减少计算

**连续解码、跟踪时间状态；只在选定关键帧建立或补充几何模型。** 人、车、机器人不能因为无需更新外形就停止记录运动。所有状态沿用原视频时间戳；关键帧序号不能替代时间，也不能把现有均匀 32 帧实验用于判断短暂接触、快速经过或关节动作。

建模关键帧由首次出现、新的可见面/视差、清晰度和当前覆盖缺口选择。已有刚体模型在其余帧只更新位姿；人体和关节对象复用身体/部件几何，更新根位姿和关节；确有新几何证据时才更新模型版本。重新出现需要验证身份和定位，不自动重新创建同款模型。建模间隔较长不等于运动轨迹可以同样稀疏。

固定分辨率、活动对象数和处理窗口后，预算可粗记为 `O(N × C_track) + O(M × C_model)`：`N` 是连续处理帧数，`M` 是选出的建模关键帧数，`C_track`、`C_model` 分别是相应平均成本。减少 `M` 主要减少深度/几何建模工作，不能消除连续解码、掩码传播、身份与姿态跟踪的 `N` 项；全局地图优化、对象数量和分辨率的成本另计。这是工作量拆分，不是当前模型实测复杂度或速度承诺。

本项目尚无上述动态链的吞吐、内存和漏事件实测。必须用同一短片分别记录解码/跟踪、姿态、建模、导出用时与 `N/M`，再比较关键帧减少前后的模型覆盖、身份错误和事件时间差。不能事先宣称固定 FPS 足以捕捉所有运动或满足安全判断；时间分辨率不足时保留事件发生区间及不可判定状态。

## 最小数据约定

以下是处理链必须能表达的概念字段，实施时放进现有实体、观测与版本契约，不创建另一套对象注册表。变换方向固定为局部到房间坐标；缺失值用 `null` 和原因，不能用零或单位矩阵表示失败。

| 记录 | 最小字段与约束 |
|---|---|
| 输入帧 | `video_sha256, frame_id, timestamp_s, rgb_ref, image_domain, intrinsics_ref`；原视频时间严格递增，缩放/裁剪变换可追溯 |
| 地图与相机 | `map_revision, units, scale_evidence, frame_id, T_world_camera, tracking_status`；模型预测尺度与独立标定分开 |
| 实体 | `entity_id, kind, potential_mobility, geometry_ref, geometry_frame, provenance`；移动潜力与当前运动状态、是否拥有独立模型分开；人对应骨架/简单身体，刚体对应独立模型，关节对象的几何引用包含部件与关节结构 |
| 时间观测 | `entity_id, frame_id, timestamp_s, mask_ref, identity_status, visibility, motion_state, T_world_entity, joints_ref, uncertainty, reason`；`motion_state` 为 `static_now / moving / unknown`，注明多次观测及相机补偿依据；人体关节文件注明坐标域及逐关节可见性，机器人关节注明对应结构、关节值与单位；关节数据在后续阶段加入 |
| 事件 | `type, entity_ids, start_s, end_s, map_revision, criterion, value, units, evidence_refs, status, uncertainty, reason`；判据包含距离/区域定义与阈值，证据必须覆盖对应时间 |

学习模型分数不直接当校准概率；空间误差未知时不生成一个虚假的数值误差带。跨采样间隔发生的事件以可支持的时间区间记录，不伪造精确发生帧。不同时间的两个人或旧位置的家具不得一起参与距离计算。

## 验收短视频与交付证据

**当前先验收地图记忆和运动状态：** 同一房间首次绕行并返回起点，保存地图、结束进程，再从另一位置拍摄并重载定位；只通过真实匹配复用旧地图与实体。配合“移动镜头看静止对象”和“对象静止→移动→停止”的连续片段，核对相机补偿、连续身份、世界位姿及 `static_now / moving / unknown`。地图重复、身份错并、失跟继续输出有效运动或未标定时声称 m/s 均不通过。

以下各 10–20 秒短片是完整目标的后续验收清单，其中精细身体/关节与交互项在基础通过后执行。保留人工逐帧复核的身份、可见段和事件时间；需要米制结论的片段另有可对应的独立实测参考。几何/时间容差在运行前按参考精度写入该片的验收记录，不根据结果事后放宽。

| 视频 | 必须证明的行为 | 失败判据 |
|---|---|---|
| 相机移动，人及椅子保持静止 | 背景、人体根位置和椅子在房间坐标中稳定，原图与模型投影可对应 | 把相机移动判成人/椅子移动；世界位置随镜头漂移 |
| 相机移动，一人走入区域再离开 | 同一人 ID；身体与动作随时间回放；进入/离开区间能逐帧对照 | 身体留在背景形成重影；只有轨迹点没有人体模型；事件来自错时间状态 |
| 同一椅子静止→被人搬动→再次静止 | 同一对象模型和 ID、连续有效位姿与两段停留时间；人物身体动作可对照 | 旧位置残留第二个当前实体；人体/家具多位置融合；仅凭接近就判搬运 |
| 两人交叉并短暂遮挡，其中一人伸手靠近物体但不接触 | 两人身份在可验证段保持对应；遮挡状态明确；接近与接触结论分开 | ID 静默互换；遮挡期伪造已观测关节；把接近误报为接触/操作 |
| 一人坐下、站起并伸手 | 同一人体模型的关节/身体变化；手的位置不被地面投影替代 | 人作为单一刚体平移；不同姿态被平均为静态网格 |
| 车辆静止→移动→停车，人物从旁经过 | 同一车体模型按时间移动；人车距离使用同时间状态；两段停留可对应原视频 | 车被删掉、旧位置留影；每帧重复生成同款车；把相近判断为碰撞 |
| 机器人基座静止，机械臂转动 | 同一部件模型按关节状态运动；位置和区域关系使用当时机械臂几何 | 因基座不动而判断整机静止；整台机器人作为单个刚体；运动连杆没有模型 |

每段交付：原视频同步回放、静态模型、可选择的所有目标实体模型及其时间状态、时间滑块、事件表及其源帧；另保存相机状态、身份错误/中断、三维位置与投影误差、事件时间差、处理耗时和资源记录。模型缺失的实体仍列为缺失，不从交付清单删除。逐项不满足就保留未通过状态，不能用模型数量、导出成功或 fr1/room 的已有结果替代这些检查。每个新增非平凡行为须留下最小可运行检查，重点覆盖时间错配、相机运动误判、身份互换、旧位置残留和未知状态被误当有效结果。

## 一手实现依据

- [DynaSLAM 官方代码](https://github.com/BertaBescos/DynaSLAM)：动态内容剔除与静态地图；几何动态检测的 RGB-D 能力不能直接宣称已适用于本项目单目视频。
- [MaskFusion 官方代码](https://github.com/martinruenz/maskfusion)：独立运动对象分别跟踪、重建的 RGB-D 实现。用于核对表示与处理逻辑，不为首轮整套迁入旧依赖栈。
- [SAM2 官方视频接口](https://github.com/facebookresearch/sam2#video-prediction)：预训练多对象掩码传播和 ID；不提供相机位姿或房间三维运动。
- [MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python)：后续人体关节候选，人体相对坐标必须另行定位到房间。本项目尚未接入；现有二维跟踪入口也尚未在本次真实人物视频中验证。
- [CoTracker3 官方代码](https://github.com/facebookresearch/co-tracker#quick-start)：现成二维点轨迹和可见性。只有现有对应点不足以验证运动一致性时再评估接入，不因存在该模型就叠加一条推理链。
- [DynSLAM 论文](https://arxiv.org/abs/1905.02781)：区分背景、运动和潜在可移动对象，以及静止到运动的转换。
