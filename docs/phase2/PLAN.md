# Phase 2 完整计划与落地愿景

日期：2026-09-19。现状以 [HANDOFF.md](HANDOFF.md) 为准；本文件回答“最终要落地成什么、按什么顺序做、每步怎么算过”。
来源：五份只读子系统梳理（照片平台契约、EHS 规则引擎、报告发布、视频现状、ConceptGraphs 源码）＋三版不同立场的路线（EHS 价值优先／风险优先／复用最短路径）＋两份对照代码的挑错评审，再由主会话抽查关键论断后综合。本文件是计划，不是完成报告。

## 1. 落地愿景

**输入。** EHS 人员拿手机在工位或车间里走一到几遍（多角度、可多次），画面里带一个现场量过的尺寸（卷尺量的一段长度，或实测的持机高度）。不需要深度相机。

**输出：现有工位报告里的一份新报告，不是另一个产品。**

1. **空间面板。** 只由“至少 2–3 个视图互相一致”的表面融合成的车间网格。没拍到的地方是空的并标“未观测”，给出观测覆盖率。不补洞。
2. **关键帧面板。** 12–24 张挑选出的关键帧充当“照片”，每张带视频时间和帧号，掩码和三维叠加都对得上。
3. **对象清单。** 每个物理对象一条记录（ConceptGraphs 式多视角融合实体），而不是每帧一条。点开能看到它出现在哪些帧、怎样被合并的，人可以拆分或合并。少于 3 个关键帧看到的对象保持“待关联”，不参与判定。
4. **对象模型（可选）。** 参数化或生成模型可逐个开关，标明“生成、非观测、放置未确认”。**判定和测量永远只用观测到的几何，不用生成模型。**
5. **平面/CAD 视图。** 以米为单位的对象占地、操作员画的区域（疏散通道、电气柜前净空、禁入区）、间距线和不确定度带。
6. **尺度面板。** 明确显示尺度来源：“操作员实测”或“模型估计”，以及两者是否一致。
7. **EHS 判定。** 每条规则给出 通过／未通过／需复核／证据不足，附测量值 ± 不确定度、所依据的帧、以及缺了什么证据。区域没看全（覆盖 < 90%）时“通过”自动降为“需复核”。
8. **时间面板。** 人进入区域的时间段表和俯视轨迹，可跳到对应视频时刻。相机没看向该区域的帧记为“无数据”，不算通过。

**最终用户仍然做不到的事（必须写进产品说明）：**
- “必须存在”类规则（灭火器、护栏、标识在位）不能靠“没看到”判未通过，只能判通过或证据不足。
- 状态类规则（门是否锁、联锁是否生效、PPE 是否戴好、带电状态）不在范围内。
- 没在词表里的危险类别和小物件（线缆、液体、小于 10 cm 的东西）看不到。
- 不是合规认证；机器结果是给人复核的证据。

## 2. 已核实的现状与结构性缺口

| 项 | 事实（出处） |
|---|---|
| 几何 | DROID 相机 + DA3 给定相机深度，352 视图：跨视角支持 90.7%，对传感器深度中位误差 2.6%（仅评估）。未验收。`modal_apps/mono_room.py` |
| 地面 | 各视图地面相差 4–16 cm；根因是 DA3 在低纹理地面的偏差，不是相机漂移；相邻视图同向偏差，跨视图投票抓不到 |
| 尺度 | 假设持机 1.6 m → 偏大 24%（实际约 1.29 m，且手持上下浮动约 ±11%）；MoGe 无真值估计与真值差 0.2%（仅一段视频） |
| 规则闸门 | `ehs_spatial/platform/policy_engine.py:210` 只在尺度状态为 `operator_anchored` 时给 通过/未通过；否则记缺 `metric_calibration / metric_footprint / metric_height` |
| **没有米制事实的生产者** | 平台里除规则引擎外没有任何代码写出“单位为米、带不确定度和来源”的占地/高度。这是照片报告 8/9 条规则“证据不足”的结构性原因，不只是尺度问题 |
| 照片报告 59/68 未关联 | `spatial.py::associate_observations` 要求最佳匹配领先所有竞争掩码 0.15；同一物体的重复掩码互相成为“竞争者”而全部落选。先做掩码去重即可大幅改善 |
| 时间规则缺陷 | `ehs_spatial/video.py::judge`：“没有人 → 区域干净 → 通过”，为固定相机而写。移动相机下“没看那边”会被判通过 |
| 视频↔报告 | 报告和发布代码里没有任何视频引用；离线导入路径（`import_scene`）没有图片数量限制，可承载关键帧 |
| ConceptGraphs | 本地有源码（MIT）。它的依赖栈很重（GroundedSAM、open_clip、faiss、pytorch3d、LLaVA）。只借“持久三维实体累积”的算法思路，不安装它 |
| 预算/磁盘 | 账本 60.36/100 美元是“预留”口径，未与实际账单对账；磁盘余 30 GiB |

## 3. 里程碑（按执行顺序）

## 4. 与用户已确认顺序的两处偏离（需要点头）

1. **薄报告导入（S5）提前到对象地图之前。** 它不调用任何模型、不花钱，之后每一步都能直接在真实报告里检查，而不是在实验查看器里。
2. **对象模型（S10）排在第一个真实判定之后。** 判定只用观测几何，模型只增加展示价值。

## 5. 需要用户拍板

1. **尺度规则。** 建议：模型估计的尺度可以参与计算，但判定封顶为“需复核”；只有每次采集的一个现场实测（卷尺量的一段长度或实测持机高度）才给 通过/未通过。1.6 m 假设只作交叉检查。是否同意改规则闸门让“模型估计”进入“需复核”而不是“证据不足”？
2. **许可。** 最终是否必须可商用？是 → S4 成为硬闸门，生成模型只能研究用或换参数化模型。
3. **首批规则。** 建议四条：疏散通道被占用、0.6 m 净距、最大堆放/柜体高度、一条“人进入区域”的时间规则。
4. **评估标注由谁做。** TUM 房间对象清单、区域进出时刻、9 条短轨迹的人物对应，各约 30–60 分钟。
5. **当前房间网格签收。** `014-edge-carve`（更干净、细边被侵蚀）还是 `012`（更完整、碎片多）作为基线。
6. **手机试拍。** 是否愿意拍一段 60–90 秒普通房间视频（棋盘格、卷尺）。它是进工厂前最便宜的域迁移检验。
7. **纯 RGB 触发失败判据时的退路。** 是否接受带深度的采集设备（如带 LiDAR 的手机）。
8. **磁盘。** 是否允许我列一份可清理的被取代实验目录清单供你确认。

## 6. 明确不做

不训练或微调任何模型；不补全未观测区域；不安装 ConceptGraphs 及其依赖栈；不在视频帧上跑照片的 `run_analysis`（会覆盖已验证的 DROID 相机）；不在全部 352 视图上跑 SAM3；不放宽任何现有阈值、不删难例来过关；不把假设值存成实测；不做跨采集的自动人员身份；人永远不是静态场景实体；不宣称合规认证。
