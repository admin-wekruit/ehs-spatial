第 4 轮独立复核：部分成立

4 项里 3 项达标

复核只在 CPU 上重算保存的数据，自己再看每段 20 张卡、20 次点击、20 个模型。数字都能复现。

  • 达标：三段视频的分割、物理信息、模型"都有"；Sam's Club 和 Walmart 的类型。
  • ME340 类型未达标：留出样本类别只对一半（0.51）。"材料 / 零件"成了兜底标签，376 张卡里 104 张，工具架、柜门、风扇、台钳大多被标成它。
  • "VLM 放最后"没做到：开头第 0.4–8.6 s 先用 Qwen 给整段视频列一个词表，SAM 3 第二波按这些词找物体，77–90% 的物体是靠这些词找到的。点击新物体时，每次点击也会单独问一次 Qwen。
  • "判定先停"没做干净：每次还有 2 个事件描述请求在问安全帽、反光背心和"安全备注"；词表请求也要了隐患类物体。判定模块默认仍开着（这次跑测手动关了，数字不受影响）。
  • 其他：模型 84–89% 仍是方块。宽度的"至多"上界对照真实尺寸有 8–28% 不成立。命名库是共享可写文件，每跑一次就变（1798→1998 行），结果依赖运行顺序。3D 面板标签用的还是旧词（"unidentified object"），不是卡片上的类型。
  • 第 5 轮会改：每段视频开头问一次 VLM 列词表（你已同意），和固定类别表 + 本地打标签模型对比，按效果选或合并；点击不再单独问 VLM；事件描述去掉安全问题，判定默认关；兜底标签改成"未识别（形状）"；命名库跑测时只读；看到的表面网格替代方块，RecGen 快速版只给复杂物体；宽度改成"未观测 / 至少"；物理数值按时间段给。

物理信息准不准（有真实尺寸的数据集）

  • 用真实相机高度：高度误差中位数 2.1–3.0 cm，顶部离地 1.6–4.2 cm。
  • 用假设的 1.6 m：顶部离地 5.7–21 cm。误差主要来自尺度，现场输入真实相机高度就能消掉。
  • 边走边拍只看到一面，所以深度大多只能给"至少 x"（有数字的只有 2–15% 的卡）。

实验结果

模型外形对上 + 部件角度

复核：部分成立

回应"模型全是方块、角度读不出来"。三段视频，每段人工看 30 个物体。

  • 看到什么画什么：用物体自己的 3D 点重建表面并上视频颜色，每个物体 14–25 ms，全部物体约 2 s。人工看：好/部分/错 38/52/0，方块是 7/41/42。
  • 部件角度：每个平面部件给出与地面的夹角 ± 误差。真实尺寸数据上中位误差 2.9°，误差范围覆盖 90.7%；按 30° 阈值能判的 235 个里 234 个判对。真正倾斜的面（15–75°）中位误差 7.6°。
  • RecGen（常驻，内部用）看起来最好：58/27/5，每个物体 7 s；SAM 3D 29/36/8；TRELLIS、TripoSR 更差；泼溅裁块边缘串色 20–53%。
  • 角度只从看到的点量；生成的模型只用于显示。
  • 复核提醒：角度的准确度偏乐观。统计只算了和真实表面方向相差 30° 以内能配上的部件，大错进不了统计；三段视频里的倾斜部件还没人工逐个看；生成模型的"看到的面"只按距离判断，没检查相机是否正对。这三点第 5 轮修。

花费 $18.1。一次内部配置的 Sam's Club 运行显存到 75.9 GiB（超 72），已提交修复，未重跑。

部件角度长什么样

每个物体的点被分成几个平面部件（不同颜色），左上角是每个部件与地面的角度 ± 误差，"1-2" 是两个部件之间的夹角。

快速 RecGen

3.3× 快
  • 每个物体 2.5 s（原来 8.2–8.4 s）；两块 A100 上 20 / 40 / 70 个物体 19 / 36 / 62 s（原来 53 / 103 / 184 s）。
  • 通过率 9.3 vs 10.0（共 19 个），在检查本身的随机波动内；形状差异 1–2%，比换随机种子还小。
  • 做法：第一阶段 12 步，第二阶段 8 步、关掉引导；只出带颜色的网格；视角成批融合；跳过 9–24 s 的导出。
  • 商用替代：SAM 3D 快速版在同一批上差不多（2.98 s，10/19）。

花费 $7.38。RecGen 仅限内部使用（非商用许可）。

分割与找全

  • 同一个物体跨帧跟住，每个物体一张 3D 卡片。
  • 完整版报告里的物体，被我们覆盖到的：ME340 53→80 / 105，Sam's 41→79 / 91，Walmart 38→61 / 74。拆碎和合错基本持平。
  • 加了开放检测框（OWLv2）交给 SAM 补漏：点真实物体能打开对的卡从 0.67 到 0.81。还漏：货架立柱横梁、上层远处货物、画面边缘的腿。

起名，VLM 放最后

  • 顺序：SAM 3 的词 → 标签库 / 零样本 / YOLOE 再有一票同意 → 同类聚簇，每簇问一次本地 Qwen。
  • VLM 问题：每段视频 45 / 14 / 19 次（第 2 轮 Gemini 要看 329 / 787 / 790 个物体）。
  • 零售认得准；车间弱：SAM 3 的词表在 ME340 上大多是"metal X"，也没有第二段车间视频来校准阈值。

早先的对照实验

LingBot 的点比快速点云细（纸箱印字、墙上的管线），但更噪；它作为可选的后台层。RecGen 在视频上也能出好模型（控制面板那一行），只从一面看到的机床会大片猜测（品红色）。

还弱的地方

  • 车间认物体：留出样本类别对 0.51–0.62。需要第二段车间视频来校准，新场景类型的第一段视频先多用 VLM。
  • 只看到一面：深度和夹角大多量不出来。拍工位时绕着走半圈就能量。
  • 尺度：假设相机高度会让米制数值偏 6–21 cm；现场输入真实相机高度即可。
  • 模型：第 4 轮大多还是方块，零售有 9–11/30 看着不对；第 5 轮换成"看到的表面 + RecGen"。
  • 已知小毛病：圆柱和框架有些面没被相机看到却标成"看到"；现场分割的卡片模型还没画进 3D；现场分割需要 GPU 容器在线。

下一步：第 5 轮

  • 每个物体：先出"看到什么画什么"的网格 + 部件角度（约 2 s，不用 GPU）。
  • 复杂物体：Jev-Omni 路由后交给快速 RecGen（内部）或 SAM 3D（商用），1–2 分钟内陆续替换；简单结构（墙、箱、货架）保持简单形状。
  • 跨时间：物理信息按时间段记录，变化超过两边误差才报；同一现场的不同视频对齐后报差异。
  • 修上面列出的已知毛病，然后三段视频重新验收。
