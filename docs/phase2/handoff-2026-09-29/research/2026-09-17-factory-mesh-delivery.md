# 工厂移动视频到真实空间网格：交付路径核查

核查日期：2026-09-17。范围：官方资料与上游源码审阅；没有安装、调用付费模型、运行重建、测量工厂数据或修改产品。OpenSpatial 固定审阅 commit `e1d779e13415449633c6f7c720681ee7afea190e`；其余文档为当日官方页面。下文“代码支持”不等于本项目已经接通，更不等于现场精度已验证。

最新目标补充：用户接受可编辑粗模型，位置正确是核心。下文检查真实观测几何的能力边界，不把精密闭合、照片级表面或每个小部件真实扫描作为粗模型的前置门槛；与编辑式模型生成结合见第 4 节。

**结论：场景位置应由同一相机坐标链上的多视角观测约束。若现有流程已有逐帧 RGB、深度、内参和一致的全局相机位姿，最短的观测表面路径是复用 Open3D 做 TSDF 融合并提取三角网格。网格融合本身不需要新增生成模型。** 但这些输入“字段存在”还不够，需验证深度单位、图像对齐、相机方向、尺度与跨工位一致性。观测网格可以是粗分辨率，用于约束可编辑部件的位置与平面。

## 1. OpenSpatial 和 SpatialLM 实际交付什么

| 模块 | 核实的输入与输出 | 对完整工厂空间的实际边界 |
| --- | --- | --- |
| OpenSpatial 3D Lifting | 有序图像/视频，经 DA3、Gemini 检测、SAM 3 分割，输出深度、相机、彩色场景点云、各物体点云与定向包围框。默认重建至多 100 帧、检测至多 80 视角、处理分辨率上限 504。 | 可提供场景几何观测和语义输入；README 没有将三角表面网格列为该模块产物。默认规模参数不能作为整厂覆盖证明。[官方 README](https://github.com/VINHYU/OpenSpatial#3d-lifting-module) |
| OpenSpatial 重建实现 | `reconstruction.py` 将每帧深度经 K 和位姿反投影，在置信度筛选后把各帧点 `vstack`，以 `write_point_cloud` 写出 `scene_stitched.ply`。 | `stitched` 在这里是点集合并；不是 TSDF 表面融合。`export_format="glb"` 调用同时传入 `export_dir=None`，也不能据此声称已导出三角网格。[固定版本源码](https://github.com/VINHYU/OpenSpatial/blob/e1d779e13415449633c6f7c720681ee7afea190e/data_preprocessing/lifting/reconstruction.py#L41-L110) |
| SpatialLM | 输入已经重建的点云；输出墙、门、窗及带语义的定向物体框。1.1 的物体类别范围是文档列出的 59 类家具。 | 适合做结构化布局/语义解释，不能把物体框当机器外壳、网栏、折板等实际表面。[官方 README](https://github.com/manycore-research/SpatialLM#introduction) |
| SpatialLM 视频示例 | 先由 SLAM3R 或 MASt3R-SLAM 建点云，再做 Z-up/轴对齐、尺度处理，最后运行布局模型。 | 示例把住宅点云高度粗略缩放至 2.5 m；这是演示假设，不能当工厂标定。示例还承认住宅训练分布导致漏检第二张沙发，对非标准布局、拥挤场景泛化有限。[官方 EXAMPLE](https://github.com/manycore-research/SpatialLM/blob/main/EXAMPLE.md) |

因此，二者都不应被描述成“输入整厂视频就得到全部机器的真实完整网格”。OpenSpatial 比 SpatialLM 更接近前半段观测几何；SpatialLM 本身主要解决后半段结构化理解。布局框可以参与粗模型定位，但不能凭框把设备内部形状称为已观测真实几何。

## 2. 已有相机和深度能否直接复用

OpenSpatial 的保存接口已具备直接融合所需的数据形态：`processed_images`、深度 PNG、confidence NPY、逐帧 K、C2W 文本矩阵及 W2C JSON。深度按米乘 1000 写入 uint16，Parquet 标注 `depth_scale=1000`；相机外参经过同一场景对齐变换。这里“metric”仍是模型输出的尺度声明，不是现场误差认证。[输出源码](https://github.com/VINHYU/OpenSpatial/blob/e1d779e13415449633c6f7c720681ee7afea190e/data_preprocessing/lifting/output_manager.py#L60-L205)

复用前只需验证这些必要契约，不需要另造一套模型接口：

1. 每帧 RGB、深度、K 对应同一次裁剪/缩放和同一像素网格；不能把处理后 K 套到原始照片。
2. 深度是相机光轴 Z 深度，单位明确；不是视差、逆深度、欧氏射线距离或伪彩预览。
3. 位姿处于同一世界系，明确 W2C/C2W，所有帧、点云、CAD 和浏览器应用相同坐标变换；不要重复做地面对齐。
4. 每帧尺度一致，真实长度有独立实测参考；尺度校正同步作用于深度、场景点和相机平移。把地面移到 Z=0 只改变坐标基准，不会校准长度。
5. 无效深度、动态区域和低可信观测被显式排除，不能仅因存在数值就参与融合。上述 uint16 毫米格式会在 65.535 m 饱和，远景若触顶必须标为无效，不能当成该距离的墙。

这些是几何输入检查的推论。上游当前按帧内置信度分位数删点，不能把该分数直接解释成“95% 量测置信区间”。是否本地已有全部合格输入，由本项目代码/实际产物审查确认，本笔记没有实跑确认。

## 3. 最短全链路

```text
移动视频及时间戳
  → 重叠关键帧（保留原帧关联）
  → 复用现有逐帧 RGB / 深度 / K / 全局位姿 / 有效观测
  → 统一实测尺度与坐标，检查轨迹和多视角一致性
  → 同一世界空间的 Open3D TSDF 融合
  → 提取带颜色的观测三角表面（粗分辨率也可）
  → 受观测约束的可编辑场景部件；导出与浏览器显示
  → CAD 使用同一场景几何坐标
  → 照片、CAD、3D 的同物体关联和独立量测验收
```

Open3D 官方直接提供 `ScalableTSDFVolume.integrate(rgbd, intrinsic, extrinsic)`；示例将 C2W 求逆后传入，并通过 `extract_triangle_mesh()` 用 marching cubes 提取网格。RGB 也可同时融合。TSDF 体素大小和截断距离要依据本次深度噪声、目标最小结构与距离设置，不能照抄家庭示例；更小体素不等于更高实际精度。[官方 RGBD/TSDF 教程](https://www.open3d.org/docs/release/tutorial/pipelines/rgbd_integration.html)

这条路径生成的是整场景观测表面。物体选择可在此表面上建立来源与语义归属；物体标签无需成为场景建模的前置条件。地面、墙、通道与设备之间的空间关系来自同一观测坐标链；观测不足的薄杆等细节可以暂不精建。该组织方式是本任务的工程建议，尚未在当前产品验证。

扩展到相邻工位时仍应保持共享坐标。Open3D 官方整场景示例已有“片段位姿 × 片段内帧位姿 → 全局 RGBD 融合”，最后一并导出全局网格和相机轨迹。它提供规模扩展的既有方法；不能据此认定长通道回环、重复设备匹配、资源占用已达标。[官方整场景实现](https://github.com/isl-org/Open3D/blob/main/examples/python/reconstruction_system/integrate_scene.py)

**COLMAP 是无需生成式形状模型的经典完整路径参照**：图像 SfM 恢复相机和稀疏结构；MVS 求深度/法线；多视角融合生成密集点云；表面重建生成三角网格，还可简化和贴图。对当前项目，应先验证可复用输入是否合格，再决定是否需要重新做前半段；不应为了“有网格”同时堆上多个重建器。[官方 SfM/MVS 教程](https://colmap.github.io/tutorial.html#multi-view-stereo)

若已知相机但没有深度，COLMAP 官方支持利用已知相机继续做稠密重建；这是另一种输入状态，不是“相机和深度都已有仍需重新建模”的理由。直接给已知相机、但没有稀疏点时，还需显式提供邻接图像和深度范围。[官方已知相机流程](https://colmap.github.io/faq.html#reconstruct-sparse-dense-model-from-known-camera-poses)

若只剩一个无序点云，Open3D 也有 Poisson/BPA 等表面方法。但 Poisson 会在低点密度处产生面并外推；平滑、封闭的网格不证明看不见的表面真实存在。本任务已有逐帧深度与相机时，优先保留并使用这些观测，而非丢失射线关系后盲目补面。[官方表面重建说明](https://www.open3d.org/docs/release/tutorial/geometry/surface_reconstruction.html#poisson-surface-reconstruction)

## 4. 与可编辑粗模型结合：用观测定位，用部件表达

若编辑式生成流程已经能产出多部件 Blender 场景，最短结合方式是给同一个场景生成过程提供既有观测约束：统一世界系、地面、设备中心/占地范围、主方向、相对间距和可观察平面；生成过程在这些位置与尺寸约束下表达设备外壳、围护等可编辑部件。无需先逐个高精扫描，也无需把每个生成部件另做一套定位。这是根据当前目标提出的工程结合方式，不是已验证的上游能力。

最小逻辑链是“照片/视频 → 共同坐标的观测位置证据 → 受其约束的部件场景 → 重新投影原图检查”。已有可靠点云或平面足以约束的部位，不必为了使用生成器先把它精细网格化；需要连续表面证据时再调用现有 TSDF。渲染审查能发现明显穿插、遗漏和方向错误，但仅凭几张漂亮视图无法独立证明真实尺度和背面位置。

交付中保留每个部件的位置依据：直接观测、由可观测平面/边界推定，或者仍待确认。用于可视化的推测细节可保留，但不把它当成量测表面。粗模型主要验收完整空间关系、可编辑性与跨照片一致定位；只有实际用于净空/折角等量测的部位，才需要对应局部的精度与不确定性证据。

## 5. Gaussian Splatting 与可量测网格

原始 3DGS 用高斯体的颜色、透明度和各向异性等参数优化新视角渲染；论文评估的是视觉质量与渲染效率。它能表现整场景，不能因此把它的 splat 当成具有明确三角面、拓扑、真实尺度与误差界的工程表面。[3DGS 作者项目页](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)

工程推论：好看的漫游画面不能单独证明通道宽度、净空、折角或薄网栏厚度正确。GS 可以是视觉浏览表示；可编辑场景则需相应部件几何。只有声称可量测的部位才须另有观测、标定和误差证据。同样，三角网格格式本身也不构成量测合格证书。无需为了这次最小验证额外引入 GS 分支。

## 6. 从住宅演示到工厂的具体差距

下表是根据上述方法原理和接口得出的工厂风险/验证设计，不是声称这些上游项目已在工厂实测失败。

| 工厂特征 | 会影响哪一环 | 单工位及扩展验证应看什么 |
| --- | --- | --- |
| 多台相同设备、重复立柱/网格 | 图像匹配、回环、实例归并容易歧义；局部看起来合理仍可能放错工位。 | 两台外观相同设备必须保持不同实例、正确左右次序和中心间距；验证跨工位控制点，而非只看框数量。 |
| 细网栏、钢丝、薄板边缘 | 像素采样、深度混合、去噪和体素融合会擦掉或加厚结构。 | 分别核对杆件、网孔与真实空隙；用近距离多视角和独立参考检查，不能只看外包轮廓。 |
| 透明护罩、镜面和高反金属 | 同一图像像素可能对应背景/反射，未必对应该物体表面。 | 单独列出有效观测不足的表面；检查是否生成虚假墙面或跨越真实通道的面。 |
| 人员、叉车、运动机构 | 静态多视角一致性遭破坏，融合后可能出现重影或拖影。 | 明确采集的静态时刻；记录剔除的帧/区域，动态遮挡留下的未观测区域不算已覆盖。 |
| 高厂房、狭长通道、遮挡背面 | 长轨迹漂移、视差/重叠不足、距离噪声和相邻片段错位。 | 查轨迹跳变、回环误差、双层地面/墙面；相邻片段重叠处比较几何，单点尺度对齐不够。 |
| 面积、帧数、细节量增长 | 相机优化、深度、体素、网格和浏览器分别占用不同资源。 | 记录每阶段耗时、峰值内存/显存、有效帧与面数；分辨率下降引起的网栏缺失也要计入结果。 |
| 真实尺度 | 单目几何或模型尺度先验不能自行充当现场标尺。 | 使用实测参考建立尺度/坐标，另留独立长度和点位验误差；不能用“普通厂房应该多高”代替。 |

官方采集建议本身已要求足够纹理、相似光照、视角间位移和高重叠，并提示避开高光；视频可抽帧，堆更多相似帧会增加耗时。[COLMAP 采集原则](https://colmap.github.io/tutorial.html#structure-from-motion) 住宅 demo 因而只能证明方法在该输入上可展示，不能外推为整厂完整性、量测精度或吞吐量证明。

## 7. 最小 benchmark：单工位 → 两相邻工位及通道

这是一份建议验收集，不是已完成结果。第一段选一个包含设备、围护、地面和一段通道的真实工位；第二段增加相邻工位，并保留连接通道和重叠采集区域。两段使用同一流程、参数记录和世界坐标。可编辑部件允许粗化，但不得靠没有观测依据的逐物体摆位来宣称位置正确。

先列出范围内的实物/表面清单与测量容差。容差应来自本次用途；若尚未定义，只报告误差，不宣称“量测通过”。最小参考包可用现场实测控制点建立坐标，再保留不参与标定的若干长度/点位，并保留少量独立复核照片。不能拿同一条用于调尺度的距离再次证明精度。

| 验收项 | 必须留下的可检查证据 | 不通过的典型情形 |
| --- | --- | --- |
| 可编辑完整空间 | 可加载的部件场景，设备、围护、地面与通道同场景浏览；列出几何类型与面数，能选择和编辑部件；保留观测点云/表面作空间证据。 | 只展示识别框却宣称已有可编辑场景；部件位置无共同观测依据。 |
| 同一物体 | 范围内清单逐项关联照片区域、CAD 元素、3D 面/组件；从三者任意一处选择均指向同一实物；保留原帧 ID。 | 漏物体、误合并相同机器、同物体重复出现、点选与几何不一致。 |
| 全局位置 | 物体全局位置、朝向、相邻设备中心距、通道宽度及独立控制点残差。 | 单物体漂亮但悬浮/重叠、工位间错位，或选中后用局部坐标掩盖摆位错误。 |
| 相机轨迹 | 每个保留帧的时间戳、K、位姿、可视轨迹、未注册帧清单；闭合路线的接缝/回环残差。 | 轨迹跳跃到另一台相同机器，漏注册未披露；仅低重投影误差却全局比例错误。 |
| 覆盖和空洞 | 按实物/表面列“已观测且建面/观测失败/未拍到”；独立复核视角的轮廓覆盖与深度/表面偏差；保留空洞位置。 | 用照片可见区域覆盖率冒充全部表面完整率，或把未观测洞补成实面后算完成。 |
| 薄结构和错误表面 | 原图、粗模型和观测几何并排检查；记录哪些细节已简化。对量测用途再加局部参考。 | 网栏变墙、护罩/反光形成虚假表面并被当成真实通道或净空边界；简化未披露。 |
| CAD 一致性 | CAD 平面表达由同一实际几何和变换产生，反向选择可回到对应表面；注明是投影还是指定高度切片。 | 从包围框投影得到伪轮廓，或 CAD 与浏览器使用不同物体位置。 |
| 量测及不确定性 | 每条量测的参考值、估计值、绝对/相对误差、支撑帧、尺度依据；复测差异；汇总中位数、P95、最大误差及未测项。 | 只报平均误差；从单次预测置信分数编造毫米误差界；遮挡不足仍输出确定尺寸。 |
| 时间和资源 | 抽帧、相机/深度、融合、网格输出、浏览器加载各阶段及总耗时；硬件、峰值 RAM/VRAM、磁盘、帧数/分辨率/面数。 | 只报模型推理速度；把文档 demo 数字当本厂速度；未计前后处理和加载。 |
| 实际浏览 | 相同硬件/浏览器记录首次可交互时间、旋转/平移/选择体验及内存；单工位与扩展场景各走一遍。 | 只有离线文件或录像，实际报告打不开、选错物体、冻结或无法自由查看。 |

量测不确定性至少要涵盖现场参考误差、尺度误差、位姿漂移、深度误差及表面采样。没有独立参考时可以报告重投影/多视角一致性，但不能将其等同真实三维准确度。必须分别统计有观测区域和未观测区域，不能用模型“补齐”掩盖缺测。

**下一步的最小决策是核对现有相机/深度产物能否通过第 2 节契约，然后在单工位上运行现有 Open3D 融合并完成上述证据。** 只有单工位达到约定用途，才用相邻工位和通道检查全局一致性与资源增长；目前没有任何运行结果足以宣布整厂交付已完成。
