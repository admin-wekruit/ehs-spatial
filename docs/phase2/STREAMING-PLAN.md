# 一次成型的流式 Panoptes：计划（2026-09-27）

来源：11 个 agent 的规划工作流：5 个摸清现状，3 个各自出架构，1 个评判合成，2 个挑错；挑错的修正已全部并入。
标注：(M) 表示我们实测过，(E) 表示估计或厂商数字，未复现。

## 1. 结论

**只把现在的离线流程自动化还不够快。** 就算一个手工步骤都不剩、模型不换，Walmart 最长的一条依赖链
（DROID → DA3 → 融合 → SAM 2.1 → 物体图 → 命名 → SAM 3D → RecGen → 盒 → 导入）仍要约 4.6 小时 (E)。
其中逐个物体串行生成占机器时间的 55–65%、费用的约 80% (M)。

所以拆成两层：

- **实时层（秒级）**：只输出观测到的东西，包括人、移动设备、EHS 告警和不断长大的观测地图。
  不做推断补全，永远不等精修层。
- **精修层（分钟级）**：就是现在这整条流程，全部自动化，按"闭合子图"跑（见 §3），不再按整段视频跑。
  它产出完整模型、泼溅、稠密图和推测地面；这些要先过自动闸门，才能以补丁形式进入实时场景，
  不过闸门就丢弃。

"一次成型"的具体含义：
1. 每个摄像头在 `site.yaml` 里一行配置，一条命令 `panoptes up` 启动。
2. 这次每一个手工决定都改成代码规则，并配一个回放测试，必须重现这次手工的结果。
3. 还没被闸门证明的推断类型默认关闭，也就是留空。

**你的两个质量目标从哪来：**
- LingBot 级细节和完整物体模型都需要多视角。单个固定摄像头只有一个视角，给不出留出视角，
  所以永远做不出经过检验的完整模型。
- 因此每个现场安装时做一次自动的**走查**：拿手持或推车上的相机走一圈，由精修层建出现场地图和完整模型。
  之后每个固定摄像头都用 `register_cut_shot` 同一套闸门配准进这张地图。
- 实时流在这张图上叠加人、变化和告警。场景变化较大时自动触发局部重建。

## 2. 架构

```
site.yaml ─> panoptes up        每个摄像头：id、流地址（只写密钥引用）、固定/移动、区域、可选 2–3 个实测点
RTSP ─> 接入：带时间戳（PTS + NTP 墙钟 + 单调时钟）、去畸变、保留全画幅；
        只处理最新帧，丢的帧记为覆盖缺口；冻结帧/黑屏/遮挡/剪辑切换检测；72 h 环形缓存（人脸在存盘前模糊）
  ├─> 实时层（常驻 GPU，只输出观测数据）
  │     T0 人/移动物：SAM 3 检测 + 跟踪 → 脚点检查 → 规则（带覆盖判断）→ 告警（本地看门狗，不依赖云）
  │     T1 几何：固定 = 安装时的地图；移动 = LingBot 逐帧 → 位姿可信规则 → 体素补丁（带 lastObservedAt）
  │     T2 物体：SAM 3 EHS 词表 → 3D 累积 → 3 个一致视角后稳定 → 置信度达标才命名
  └─> 精修层（任务队列，可抢占，有花费上限）= 现有流程按闭合子图跑
        R1 DROID + DA3-BASE → TSDF → 贴图/补洞
        R2 SAM 2.1 → 物体图 → SAM 3D ∥ 盒（并行容器）→ assess() 闸门 → 代码合并
        R3 推测地面（自检）、泼溅（只显示）
        每个结果 = 补丁 {provenance, gate, basedOnSeq, supersedes}
平台：scene_events（只追加、序号连续）← 接收端：没过闸门的推断返回 422，再做一次反驳复检
  ├─ GET events?after=N（长轮询）→ 查看器 #/live（按 key 增量更新）
  └─ 头部摘要变了才打检查点（内容寻址）→ 发布快照；静态站只留给对外分享
```

## 3. 关键设计点（含挑错后的修正）

- **精修层的单位是"闭合子图"**：DROID 全局 BA、DA3 一次性推理、融合投票、最佳视角贴图、留出判定，
  都是按整段做的，改成滑窗会改变结果，这次校准的测试也就作废。所以只在子图"闭合"时才跑，
  且原样跑整段流程，现有测试照样适用。闭合条件任一满足：
  - 遇到剪辑切换；
  - 跟踪丢失；
  - 相机离开该区域超过 N 秒且关键帧数 ≥ K。

  子图之间只通过 Sim3 闸门拼接。
- **固定摄像头**：安装时算一次：镜头（MoGe-3 加直线去畸变）、底图深度、地面，再配准进走查地图。
  之后只有"结构/深度变化"测试触发才重算，不用亮度变化（否则黄昏/红外切换会误触发）；每种光照模式各存一张底图。
- **移动摄像头**：用常驻的 LingBot 逐帧跑，再加位姿可信规则。重启或跟踪丢失后，用存下来的关键帧和描述子
  经同一套闸门重定位；定位不上就开一个标记为"未配准"的新子图。
- **尺度**：接入唯一的尺度函数 `contract_scale`，新增一个 `measured_reference` 状态：
  至少 3 个实测点，留 1 个检验，残差 ≤3%。没有实测尺度时，所有距离、速度规则一律给"需复核"。
  移动相机的尺度来源可以是：实测的安装高度、已知尺寸的标记，或者手机 ARKit/ARCore。

## 6. 推断政策怎么在线执行

1. **没有覆盖就没有 PASS。** 规则只有在它的区域整个时间窗都被看到时才能通过：
   - 区域在画面里完整可见；
   - 画面不是冻结或黑屏；
   - 检测器在线。

   否则给"无数据"。现在 `video.py:747` 在没检测到人时直接给 PASS，要改。
2. **脚点抬到 3D 要先检查。** 按 bbox 顶部推出的身高在 1.3–2.1 m 之间，脚点位置没有被遮挡，
   框不碰画面边缘，脚点落在观测过的地面上。任一条不满足就给"需复核"。
3. **速度按至少 2 秒的固定基线回归计算**，与采样率无关。超过物理上限的跳变只让那段轨迹作废，
   不判 FAIL。现在的速度区间会随采样率变宽，`video.py:732` 要改。
4. **每个告警要 3 帧一致**，延迟超过 5 s 标记为 `degraded`。
5. **观测几何也会过期。** 每个体素和实体记录 `lastObservedAt`；区域重新被看到时，
   自由空间反驳对观测几何同样生效；超过时效没再看到就给"无数据"。
6. **推断分类型自检**：安装时和每晚各跑一次噪声、抬高对照、隐藏块测试，不通过就关掉这一类推断并告警。
7. **精修补丁的入场条件**：过 Sim3 闸门，并且对它 `basedOnSeq` 之后到达的所有视角再做一次反驳复检。
8. **"确认"永远由人来做。** 接收端拒绝任何带 `confirmed` 的补丁。

## 7. 运维和安全

- **时钟**：接入时每帧打三个时间戳，各设备跑 NTP/chrony；跨摄像头时差超过 100 ms 就关掉跨摄像头规则。
- **断线**：本地看门狗独立于云发出"摄像头/检测器离线"。至少 2 个常驻副本，或者一个本地 CPU 兜底检测器。
  RTSP 断开后按退避重连。
- **凭据**：`site.yaml` 里只写 Infisical/ATM 的密钥引用。每个摄像头一个只能 `POST blob/event` 的生产者凭据。
  视频走 RTSPS、SRT 或 VPN。权重镜像到内部仓库并锁 sha256，运行时不从 Hugging Face 拉取。
- **隐私**：
  - 存盘的内容一律先模糊人脸，只有检测器能看到原始帧。
  - 人物片段和关键帧用按时间段轮换的密钥加密，保留期一到就销毁密钥（crypto-shredding）。
    日志本身不改，只留墓碑记录，这样不和不可变约束冲突。
  - 告警发生时，前后各保留 10 秒作为证据。
- **存储**：检查点只在头部摘要变化时生成，按内容寻址去重。否则每 60 s 一个完整文档，
  一天约 8 GB 且永远删不掉。
- **评测**：建一个带标注的事件集：MEVA 加上试点现场的视频，标注区域闯入、接近、速度，
  另有夜间、遮挡、人群（超过 32 人）子集。按事件的准确率、召回率、每小时误报数验收，
  不能只回放这三段演示视频。

## 9. 需要你来定的事

1. **先做固定摄像头还是移动摄像头？** 建议先做固定的，M0 用 MEVA 视频。
2. **先上云还是先上本地？** 超过几个摄像头后本地更便宜，常驻的云 GPU 按小时计费。
3. **安装时的人工输入：** 每个摄像头画区域、测 2–3 个点，每个现场再做一次走查。
   不做的话，所有距离规则都只能给"需复核"。这算不算你说的"手工推"？
4. **M0 的 GPU 探测**：3 次有上限的调用，约几美元 (E)。
5. **商用替换：**
   - DA3-GIANT 换成 DA3-BASE；
   - `serving/mapanything_service.py` 和 `providers/map_anything.py` 目前加载的是 CC BY-NC 版的 `facebook/map-anything`，
     要换成 `-apache` 版。
6. **LingBot-Map 权重的许可**要书面问 Robbyant。拿不到的话，移动摄像头改用 DPVO + DA3，细节会少一些。
7. **SAM License**：这几个需要申请的权重能不能打包进一体机交付？
   公司账号要申请的是 `facebook/sam3`、`sam3.1`、`sam-3d-objects`。
8. **人员数据的保留期**，以及人脸要不要模糊。

## 10. 已定的决定（2026-09-27）与据此修订的路线

**已定：**
- 先做移动摄像头；
- 先跑在云上（Modal）；
- 批准 M0 的 GPU 探测；
- 安装和走查改成一个手机 App 来做。

**手机 App（ARKit，iOS 优先）。** 移动摄像头最难的三件事是位姿、米制尺度和重定位。
iPhone/iPad 的 ARKit 在设备上已经实时做好了：
- **米制位姿：** ARKit 以 60 Hz 给出米制相机位姿（视觉加惯性），相机轨迹和速度直接可用，
  不用 DROID 或 LingBot 去估位姿，也不用测量点来定尺度。我们以前验证过一段 ARKit 采集，
  持机高度 1.497 m，和真值对得上。
- **深度：** Pro 机型有 LiDAR，每帧直接给米制深度。没有 LiDAR 的机型用 DA3-BASE 深度，
  再按 ARKit 的特征点对齐尺度。
- **地面和区域：** ARKit 自带平面检测，找到地面后，区域可以直接在 App 里的地面上画出来。
- **重定位：** ARWorldMap 可以保存地图，下次回到现场重新定位，也支持断线后恢复。
- **已有代码：** 管线已经支持 ARKit 采集。`prepare_arkit_clip.py` 会跳过 DROID，
  尺度状态记为设备米制，距离规则能给出通过或不通过，不必再给"需复核"。

Android 用 ARCore（有 Depth API，但多数机型没有 LiDAR）。没有 ARKit 的普通视频
（比如 YouTube 或 CCTV）继续走 LingBot/DPVO 那条路，细节少一些，尺度靠估计。
