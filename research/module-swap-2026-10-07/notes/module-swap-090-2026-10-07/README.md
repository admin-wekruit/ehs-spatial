# 090 模块替换：同一流程，只换两个模块（2026-10-07）

流程不变（见 `RUNBOOK.md`，S1–S14）。只在两个模块接口处换输入：几何 Pi3X → MVS，补全 RecGen → SAM 3D。四个版本的组装代码、掩码、照片、择优规则完全相同。物体清单 9 个，四个版本一个不少。

| 版本 | 几何 | 补全 | 可商用 |
|---|---|---|---|
| pi3x+recgen | Pi3X | RecGen | 否（原报告） |
| pi3x+sam3d | Pi3X | SAM 3D | 否（几何非商用） |
| mvs+recgen | MVS | RecGen | 否（内部对照，只用来分离几何的影响） |
| mvs+sam3d | MVS | SAM 3D | **是** |
| mvs-fill+sam3d | MVS + 掩码内补洞（几何模块第 2 版，见下文） | SAM 3D（在补洞几何上重新生成） | **是**（MoGe-3 为 MIT） |

第一层对比（组装 / 生成 / 几何的 JSON）：`table.md`（含每一列和每个指标的解释）。逐物体对比图：`cmp-pi3x/*.jpg`（Pi3X 几何）、`cmp-mvs/*.jpg`（MVS 几何）。

## 结论（第一层）

**换补全（RecGen → SAM 3D），几何固定**
- Pi3X 几何：9 个物体轮廓 IoU 平均 +0.056，边界误差降；深度残差 +1.3 个点。两根防撞柱不再插地（−1.7 / −0.8 → +3.6 / +0.9 cm），左光幕下部补回（最低点 45.8 → 24.2 cm）。
- MVS 几何：IoU 平均 +0.099，深度残差 −0.64 个点，边界误差 −0.27 个点。点图稀的时候 SAM 3D 比 RecGen 稳得多：RecGen 在 MVS 上把左光幕生成成 33×25×278 cm 的长条、插地 95 cm、IoU 0.39。
- 防护板：两种几何下 SAM 3D 都给出厚块（高 66–86 cm，实物约 40 cm）。Pi3X 下深度残差 8.9% 判为不可用；MVS 下 4.9% 没被这一层的门拦住，但形状同样不对。

**换几何（Pi3X → MVS），补全固定**
- 现场值更准：右罩壳下沿 24.0（现场 24）对 23.4；右横杆 21.0（现场 20）对 22.7；五张照片相机高度极差 1.7 对 6.3 cm；急停约束 3.3% / 2.98%，都通过。
- 物体轮廓变差：IoU 平均 −0.096（RecGen）/ −0.053（SAM 3D）。原因是掩码内点图覆盖率从 98% 降到 55%（左光幕 21%，防撞柱 30–35%，左围栏 30%）：补全模块拿到的深度不完整。
- 摆放变弱：MVS + SAM 3D 的左围栏、左右防撞柱组装后落在地面以下 76 / 10 / 8 cm，靠"切掉地面以下"修正才贴地。深度项的点少，组装就定不住高度。

**两个都换（MVS + SAM 3D）对原版（Pi3X + RecGen）**
- 轮廓 IoU 平均 0.796 对 0.792，持平；深度残差 2.4% 对 1.7%，略差；现场值误差 0.6 对 1.4 cm，更好。
- 每个物体都有模型，没有下沉、悬空，没有轮廓不符。

**这一层看不见的明显错误（第二层才能查）**
- 模型缺一段：右光幕的照片 2 候选 IoU 最高（0.74 / 0.67），但高 109 / 117 cm，最低点 73.7 / 64.8 cm，下半截没有。按轮廓和深度它是最好的候选，按尺寸它不对。
- 模型过长：MVS + SAM 3D 左围栏 377 cm（原版 227 cm），防护板 210×215×66 cm。
- 防护板后板位置（点图条纹错配）。

这些要靠原流程的后段：盒子 / 面（S12）、下沿（S11）、三视图平面（S10）、G1–G8（S14）。所以"没有明显错误"要等第二层对比。

## 结论（两层合起来）

- **补全 RecGen → SAM 3D：可以换。** 同一流程下轮廓持平或更好，G1–G8 明显错误 8 → 0，三视图折角不变。防护板仍是两种补全都做不好的物体。
- **几何 Pi3X → MVS：测量更准，模型更差。** 现场值误差 1.4 → 0.6 cm；但点图覆盖 98% → 55%，补全模型轮廓平均 −0.05 到 −0.10，摆放定不住高度（3 件插地），地面覆盖再降 10 个点。
- **两个都换（可商用）对原版：** 轮廓持平、现场值更准、明显错误 3 个（全是插地，比原版的 8 个少，但不是 0）。要做到"没有明显错误"，几何这一侧要补点图空洞（MoGe-3 在掩码内补洞 + 重新生成），或者在组装里加地面接触约束；补全这一侧防护板要用三视图平面重定深（原流程 S10 的后半步）。
- **补了点图空洞之后（第 5 列，mvs-fill+sam3d，可商用）：** 现场值一个没变（24.0 / 21.0，MAE 0.60）；补全模块拿到的深度 55% → 85%；轮廓 IoU 0.795 → 0.833，比原版高 0.04；明显错误 3 → 2（右防撞柱贴地，左围栏插地 75 → 32 cm）。剩下的两件（左围栏、左防撞柱）底部在照片里看不见，补洞补不到，组装的深度项定不住高度——这是组装（S5）的事，不是几何或补全模块的事。**当时的判断：补全换 SAM 3D 可以用；几何换 MVS + 补洞可以用（测量更准、轮廓更好、不改现场值），但"零明显错误"要在组装里加地面接触约束才能做到，那是改流程，当时没做。**（之后批准了，见下文"组装第 2 版"和"结论（最终）"。）

## 几何模块第 2 版：MVS + 掩码内补洞（第 5 列 `mvs-fill+sam3d`）

上面的结论说 MVS 这一侧要补点图空洞。做法仍在几何模块内部，输入输出契约不变（`geometry/frames/<f>/{pts3d, conf, valid_mask, intrinsics, camera_to_world}.npy`），流程其余各步原样重跑；SAM 3D 的输入点图变了，所以候选重新生成（`swap-runs/mvs-fill-ab`），择优规则、组装代码、各项检查完全相同。

**做法（`fill_geometry.py`）**：同一 MVS 点图（`bbab-export-090-mvs-scipyba`），只在 9 个物体掩码内、MVS 没有点的像素上，用 MoGe-3（MIT，已镜像）的单目深度补点：
1. 比例 s：每张照片一个，MoGe 深度对 MVS 深度的全局 Huber 拟合（10–13 万像素）。每个物体自己拟合时在薄物体上病态（光幕两张照片拟出负比例），所以不用。
2. 偏移 t：每个物体一个偏移场，而不是一个常数——物体自身 MVS 像素上的残差 z_mvs − s·z_moge 做归一化卷积（σ = 48 / 24 / 12 px，细尺度有足够支撑时覆盖粗尺度；都没有时用物体中位数）。补上的点与旁边的 MVS 点连续。
3. 不补的像素：掩码边界 3 px 以内；MoGe 深度在 5×5 像素内跳变超过 5 %（物体边缘，单目深度在那里是混合值）；被两个物体掩码同时覆盖的像素（SAM 3 掩码有重叠：右围栏 / 右光幕约 2000 px，没有唯一归属）；补出的深度超出该物体自身 MVS 深度范围 ±max(3·MAD, 10 cm) 的。
4. 补的点 conf = 0.3（原 MVS 点 1.0；内容规则 conf ≥ 0.1 之内）。地面、急停像素一个都不动，所以尺度和地面与 MVS 版逐位相同。

**为什么是这三条"不补"规则（如实记录三次迭代）**：第一版（物体常数偏移）把右罩壳下沿的现场值从 24.0 量成 18.9 cm；查到原因是公平评判器对罩壳表面拟合的自由平面被 7 个补出的点带偏（倾角 8.8° → 57.6°）。第二版（偏移场）左罩壳回到 23.5，右罩壳反而 12.2（倾角 61°）。再查：那 7 个点不是光幕自己的——它们在右围栏掩码里（两个掩码重叠），按围栏的深度补出来，落在罩壳掩码的边缘上。于是加了重叠、边界、边缘三条规则，右罩壳 24.0、左罩壳 23.7，平面倾角回到 8.8° / 11.7°。每一版都用同一个评判器（`backbone_ab_modal.py analyse`，Modal 上原样跑）重新算过，不是本地改数。

## 组装第 2 版：地面接触约束（"组装v2"列）

前面说"零明显错误要在组装里加地面接触约束"，批准后做了。以前做过的两次都是**事后修**：`completion-ab-090/compare.py floor_fix`（组装完切掉地面以下、落地物体下移，②对照层用的）和 S12 盒子层的贴地吸附（`workcell-boxes/build.py`，动盒子不动模型）；S5 的 9 自由度优化本身只有轮廓 + 边界 + 深度三项。这次改的是 S5 本身。

**改动（`panoptes-serving/scripts/research/assemble_lucida_scene.py`）**：`refine()` 的损失加一项 `floor_penalty`：模型最低点（顶点高度的 0.5 百分位——和地面检查、G2 门同一个统计量）低于 `evidence/floor.json` 的地面平面就罚，罚量 = 2 × 下沉量 / 物体自身高度（无量纲，一个权重）。只罚下沉，不拉悬空：机器人、防护板、光幕是挂装的，不能有"落地物体"的类型规则。自检：贴地 0、悬空 0、下沉 10 % 高度 = 0.2。记录写进 `comparisons.json` 的 `refinement.floor_contact` 与 `final.floor`。

**怎么比**：五个版本的运行目录各复制一份（`swap-runs/v2/<版本>`，含原版 Pi3X + RecGen 的 `lucida-replica-01` 副本），同一个 Modal 组装应用重跑 S5，然后 S6–S14 原样（`run_v2_chain.sh`）。表里"组装v2"列与旧列并排，旧列不动。

## 结论（最终）

- **补全 RecGen → SAM 3D：换。** 同一流程下轮廓持平或更好，明显错误 8 → 0（原几何上）。
- **几何 Pi3X → MVS + 掩码内补洞：换。** 现场值误差 1.4 → 0.6 cm（补洞不改现场值），补全模块拿到的深度 55 → 85 %，轮廓 0.823 对原版 0.793。
- **组装加地面接触罚项：加。** 一个无量纲罚项，无类型规则；五个版本插地全部清零，轮廓代价 ≤ 0.01。
- **可商用组合（MVS + 补洞 + SAM 3D + 组装 v2）对原版（Pi3X + RecGen + 组装 v1）：** 明显错误 0 对 8，轮廓 IoU 0.823 对 0.793，现场值误差 0.6 对 1.4 cm，深度残差 2.7 % 对 1.7 %（略差）。
- 仍未解决、与模块无关：报告级 G1 地面覆盖（平台侧地面面片，三个新版本都 75–77 %）；防护板（两种补全都做不好，要 S10 的三视图平面重定深）；下沿实测在换掉的模型上多被两视图检验拒绝（现场值以几何层评判器为准）。
